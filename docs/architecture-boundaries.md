# 代码架构边界

状态：当前代码边界规范  
更新日期：2026-08-24  
当前模块工作和验证范围见 [开发控制台](development.md)。

本文件冻结“谁拥有规则、谁能改状态、依赖怎样流动”。它不是迁移完成报告，也不以历史阶段名称定义当前开发顺序。

## 总体结构

```text
trpg_server/
├── core/       权威基础设施、事件、投影、事务、存储、API
├── characters/ 人物、关系、认知、身体与人物决策规则
├── items/      物品、容器、所有权、交易和 AI-物品资料工具
├── locations/  运行时地点、出口、移动、环境
├── map/        图册、街道拓扑、路径和公开地图读模型
├── behavior/   玩家输入路由、命令协调和日常规则
├── story/      剧本、场景、调查、线索与剧情事件
├── world/      时间、天气、法律、经济、组织与世界结算
├── ai/
│   ├── platform/ 模型底层交互与适配器
│   └── player/   玩家意图、叙述和可见结果安全层
├── memory/     确认事件派生的长期记忆与检索
└── evaluation/ 跨领域评估工具
```

网页是展示、输入和调试层，不拥有最终游戏规则。

## 不可跨越的权威边界

1. Python 后端的确认事件与可重放投影是游戏状态的唯一权威。
2. 玩家输入、AI 输出、图册、检索结果和叙述文本都只能提供请求、候选或只读资料，不能直接写入状态。
3. 任何重要状态变化必须先经过所属领域校验，再形成带来源的确认事件。
4. 叙述只描述已确认结果；重新生成叙述不得重新结算规则。
5. 前端不能复制最终判定、物品所有权、关系、通缉、骰子或移动/天气时间计算。

完整不变量见 [核心原则](core-principles.md)。

## 领域职责与禁止事项

| 领域 | 拥有 | 不得拥有 |
| --- | --- | --- |
| `core` | 事件/命令协议、投影聚合、回放、幂等、事务、存储和 API | 人物、物品、地点或剧情业务规则 |
| `characters` | 人物状态、关系、认知、身体限制和 NPC 规则 | 直接修改物品实例或模型 HTTP 实现 |
| `items` | 定义、实例、容器、数量、容量、所有权和物品候选计划 | 决定 NPC 意愿、地点营业或剧情推进 |
| `locations` | 出口、移动许可、环境机会和跨地点天气加时 | 创建交易、替人物决定行为或写物品所有权 |
| `map` | 静态地图事实、路径和只读占用/公开读模型 | 作为第二套可写世界状态 |
| `behavior` | 玩家请求的本地解析、命令协调和复合行为顺序 | 绕过领域校验直接写投影 |
| `story` | 剧本来源、场景、调查、时钟和剧情候选 | 直接决定 NPC 社会结果或模型传输 |
| `world` | 时间与世界结算候选、天气事实、法律/经济规则 | 绕过核心提交世界变化 |
| `ai/platform` | 模型配置、HTTP、超时、重试、解析和审计 | 数据库/投影写入或确认事件 |
| `ai/player` | 玩家可见 AI 候选、叙述安全和降级 | 直接创建事件或隐藏事实 |
| `memory` | 确认事件的记忆派生、检索和摘要 | 作为当前事实或写回投影 |
| `evaluation` | 读取状态和事件进行测试/评估 | 运行时领域判定 |

## 允许的依赖方向

```text
领域 -> core 协议、确认事件与只读投影
behavior -> characters / items / locations / story / ai / memory 的公开端口
characters -> items 的只读摘要或物品命令；可读取 AI/记忆候选
locations -> story 的只读地点机会来源
items -> story 的只读故事绑定策略
map -> core/locations 的只读状态，输出图册和派生读模型
world -> core 事件协议，输出经验证的候选
ai -> 领域提供的裁剪上下文，输出结构化候选
memory -> core 的确认事件与只读投影
```

反向协作只能通过明确端口、命令或确认事件完成。下列依赖必须保持禁止：

- `characters -> items` 的内部写入；
- `locations -> items` 的创建/交易写入；
- `ai -> core/store` 的写入；
- `story -> characters` 的 NPC 结论写入；
- `items -> characters` 的私密认知读取；
- `memory -> 当前权威状态` 的反向覆盖。

## 当前已知过渡边界

- `Projection` 和若干人物/地点状态数据类仍在 `core/state.py`。这是当前可回放的聚合边界，不表示这些领域规则属于核心；状态类型迁移必须独立验证。
- `behavior/commands/` 已做领域分组，但部分实现仍委派给 `behavior/router.py` 私有函数。禁止将新业务继续堆进总路由器。
- DeepSeek 的 NPC、日常和叙述适配器尚未全部物理迁入 `ai/platform`。现有路径必须只返回候选；抽离时不改变事件语义。
- 历史事件兼容逻辑可以留在核心投影；没有调用方的旧业务入口不得以“兼容”为名恢复。

## 变更与验证

- 新代码先归类到单一领域；无法归类时先在 [开发控制台](development.md) 记录原因，不把业务代码塞进 `core`。
- 改变事件结构时更新 `schemaVersion` 策略、来源链和回放测试；改变上述边界时更新 ADR 或本规范。
- 删除被正式实现替代、且无调用方/脚本/文档引用的旧代码。
- 默认只运行直接相关的冒烟测试；核心事件、存储、回放、公共协议或用户明确要求时扩展验证范围。
