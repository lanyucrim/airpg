# 架构自审与遗留问题

> 文档定位：历史阶段自审记录，仅用于追溯既有架构决策和遗留风险；当前开发模块和任务以 `docs/development.md` 为准。

## 1. 自审目的

每个阶段完成前，不只检查“测试是否通过”，还要反问设计是否会在换剧本、增加 NPC、长期存档或接入 AI 后产生明显错误。发现属于当前阶段的问题直接修正；超出范围的问题必须记录下一步，而不是假装已经解决。

## 2. 本轮发现并已修正的问题

### 礼物接受错误地依附在物品上

初版通用化方案曾让物品携带 `giftPolicy=accept`。这会产生“任何 NPC 都接受红酒”的错误含义。

现已改为由接收角色声明 `acceptedGiftDefinitionIds`。默认没有 NPC 自动接受礼物。

### 非管制物品可能被默认交给玩家

“不受管制”不等于“持有人愿意赠送”。现已增加安全默认策略 `owner_discretion`：只有剧本明确配置 `allow` 时，请求才会产生转移事件。

### 模糊目标可能导致错误唯一物品转移

现在会根据动作词附近的名称和别名解析物品；如果多个实体同样匹配，返回 `ambiguous_reference`，不写事件、不推进世界版本。玩家明确点名错误持有人时也不会偷偷改目标。

### 赠礼历史曾通过关系值间接推断

关系值为零不代表赠礼没发生，某些礼物也可能不改变关系。现在投影单独保留 `gift.accepted` 历史，过去赠礼主张直接检查真实赠礼事件。

### 替代线索曾写死在钥匙判定中

现在由物品的 `refusalClueId` 指向剧本线索定义。规则只验证和执行关联，不知道“北门”或“午夜换岗”。

### 旧演示兼容层会继续污染正式开发

项目已确定只围绕《灰港：黑潮王座》开发。旧演示包、重置接口和专用兼容映射虽然曾帮助回归，却会持续制造两套产品内容。阶段 3C 第二部分已经删除这些入口；通用物品与关系能力继续由不属于产品内容的纯规则测试保护。

### 阶段 3A 开发过程中的执行问题

- 相对路径检查两次使用了错误工作目录；虽然都立即重跑且没有写入错误位置，但说明仅靠记忆路径不可靠。后续固定从仓库根目录执行仓库扫描，从应用目录执行应用测试，不在同一条命令中混用两种相对根。
- 本地后端仍运行旧进程，第一次 HTTP 检查没有出现新剧本字段；已把“验证前重启实际服务”加入固定流程。
- 路线图树形结构曾重复一行；已修正，并继续使用文档结构检查。
- 剧本清单最初包含运行时战役 ID；自审后移除，避免把模板和存档实例耦合。
- 最初仅考虑把礼物接受策略放在物品上；本轮自审进一步改为角色策略。

## 3. 当前仍然不够合理、但不应在本轮越界完成的部分

### 规则解析仍是关键词启发式

本地解析器仍以关键词和实体别名为主，适合确定性降级，不适合最终自由语言体验。阶段 4 已接入结构化 AI 候选，但 AI 仍必须经过实体、权限、资源和故事边界校验；无论使用哪种解析器，歧义都不能直接变成状态变化。

### 请求策略仍然较粗

当前只有 `allow`、`owner_discretion` 和 `restricted`。尚未表达价格、任务条件、关系阈值、阵营权限和临时承诺。后续应生成可审计的决策原因，而不是不断增加布尔字段。

### 物品数量与容量已完成首个切片，完整运营规则仍缺失

7.5D 首个交易切片已经支持堆叠物品部分转移、数量校验、容器重量/体积容量、余额、报价、购买实例化和来源链，并有数量/容量回归测试。完整商品目录、出售/退货/议价、正式账户 Schema、过期结算和网页交易操作仍未完成。

### 玩家属性仍是演示显示值

生命和专注仍由公开投影中的演示值提供，尚未进入角色事件模型。它们不能被视为已完成的通用角色系统。

### NPC 动态决策已完成基础版，完整社会自治仍缺失

阶段 4C/6 已支持带来源的 NPC 认知、关系、风险、人物档案和贿赂/赠礼候选校验；阶段 7.5F 仍需把金钱、物品、职责、日程、组织压力和更多社会行为统一接入长期自治。当前不能把基础 NPC 决策误写成完整人物社会模拟。

### 回合规则文件已经偏大

解析、社交物品交互、主张核验和复合行动目前仍集中在 `engine.py`。阶段 3C 已把移动前置条件拆到纯规则模块 `movement.py`，但事件组装和降级文本解析仍在 `engine.py`。后续增加门锁前应继续拆分实体匹配与访问规则，不能把所有新领域处理器重新堆回该文件。

## 4. 《灰港》导入与阶段 3C 第一部分自审

### 已修正：正式剧本名下放着无关演示

原 `content/campaigns/gray-harbor` 曾经承载无关演示，阶段 3C 第一部分先把它与正式内容分离。第二部分进一步删除了旧演示包和专用兼容层，正式目录现在只承载《灰港：黑潮王座》开局切片。

### 已修正：直接把整份原稿当运行状态

24,137 行原稿同时包含玩家可见设定、GM 真相、备用内容、终局资料和写作建议。全部直接导入会泄露秘密并把“可能发生”误写成“已经发生”。当前只编译白鹭屋开局；原稿继续作为内容来源，未编译内容不进入存档。

### 已修正：客观真相可能泄露给前端

版本 2 新增 `facts.json`，并为事实、组织、时钟和义务设置公开范围。玩家接口不会返回 GM 事实、NPC 私有动机或 GM 专用组织。自动测试明确搜索珍妮伪造借据、西蒙利用伪造和黑潮计划等文本，确保它们不在公开状态中。

### 已修正：移动事件时间戳倒序

初版移动事件曾先以出发时刻记录 `character.moved`，再追加到达时刻的 `time.advanced`，最后又以旧时间追加场景节拍。这会造成事件序列与世界时间不单调。现已统一为：先推进到到达时刻，再在同一时刻记录移动、场景换位和节拍。

### 已修正：组织缺少隐藏边界

如果组织默认全部公开，后续导入黑潮计划会被普通玩家枚举。组织现具有 `public/player/gm` 可见性，GM 组织保留在权威投影中但不会进入公开状态。

### 本轮执行错误

一次单测命令在仓库根目录错误使用了后端虚拟环境的相对路径，命令立即失败且没有写入任何内容。随后改回 `apps/server` 工作目录运行。后续继续遵守“后端测试只从后端目录执行”的固定约束。

### 已修正：隐藏出口曾无法动态发现

版本 3 通过剧情条件、发现定义和 `location.exit_discovered` 记录角色级发现。地窖暗道在暴雨入口暴露条件成立前不会被搜索出来；发现后才进入玩家可见出口。前端和叙述都不能直接改出口状态。

### 已修正：为了展示门锁而虚构剧本房门的风险

原稿当前开局切片没有明确说明哪扇白鹭屋房门上锁。实现因此只提供通用门锁与权威钥匙校验，并用合成规则状态测试成功和失败；正式灰港地点不添加原稿没有的锁。这样既完成架构能力，也不篡改剧本。

### 仍未解决：时钟到期没有自动事件

时钟能计算剩余分钟，但到期时尚未自动生成 `clock.expired` 及相关世界行动。不能把“剩余为零”直接当作铁钩已经接管白鹭屋；下一步的时间规则必须显式提交到期事件与后果。

### 仍未解决：线索、知识与信念还没有完整分开

版本 2 已把客观事实定义与角色初始认知分开，但线索发现、错误信念、推测置信度和信息传播仍未完成。向量检索仍不得成为这些状态的权威来源。

## 5. 阶段 3D 调查与询问自审

### 已修正：调查结果可能绕过真实物品

检查现在必须引用权威 `item`，并验证物品所在容器与行动者位置。阅读最后通牒不会自动把纸张移入背包；不在可接触位置的账本也不能被检查。

### 已修正：NPC 可能披露自己不知道的事实

最初设计只检查 `requiredNpcKnowledgeFactIds`，但剧本作者可能把另一条未知事实错误地放进 `revealedFactIds`。规则现检查两者并集，保证 NPC 即将披露的每一条事实都在其知识集合中；否则只返回不知道，不写玩家知识。

### 已修正：调查文本可能提前泄露下一层真相

早期结果文本曾写“没有揭示伪造签名”。即使是否定句，也会暗示存在伪造。现已改成“没有指出异常来源或责任人”，公开状态与叙述都不出现珍妮或伪造信息。

### 已修正：复合行动可以一回合推进多个主要节拍

`maxMajorBeatsPerTurn` 过去只被保存，没有实际限制复合命令。现在复合行动一旦达到场景节拍上限就暂停剩余组件，玩家必须在下一回合重新确认。

### 已部分推进：作者定义的回答不等于完整 NPC 心智

版本 4 能保证 NPC 在场、知道事实且话题已配置。阶段 4C 已在物品提供场景中加入 AI 对人物经济、性格、关系、风险和来源历史的综合判断，但说谎、错误信念、目标计划、通缉和传闻传播仍未完成；完整认知模型仍属于阶段 6。

## 6. 阶段 4A 第一部分自审

### 已修正：模型可能读取完整权威世界

意图解析器现在单独构造玩家可见上下文，只包含当前可见地点、出口、角色和后端允许的交互。GM 事实、角色私有备注、未发现出口和秘密标识不进入模型请求。

### 已修正：原始模型输出可能经调试接口泄密

即使输入上下文安全，模型仍可能幻觉出隐藏名称。解析请求和原始输出会写入后端审计，但普通玩家回合详情只返回解析状态、模型和失败代码，原始载荷固定脱敏。

### 已修正：模型异常可能中断权威回合

Schema 错误、领域校验失败、超时、低置信度、澄清请求和适配器异常都会降级到原有本地解析器。降级结果仍走同一套命令校验、事件提交与幂等流程。

### 已解决：第一部分尚未配置真实模型

第一部分只完成可替换适配器边界和结构化候选链，并用模拟模型覆盖成功与失败路径，当时网页仍使用本地解析器。第二部分现已接入 DeepSeek 并完成小型真实冒烟评估；未配置密钥的环境仍保持本地降级。

### 剩余风险：结构合法不等于语义正确

模型可能生成完全符合 Schema、引用也合法但误解玩家意图的候选。下一步必须以《灰港》固定评估集测量准确率、降级率和泄漏率，并为高风险动作保留澄清策略。

### 已修正：等待模型时占用 SQLite 写锁

初次真实适配时，模型调用仍位于 `BEGIN IMMEDIATE` 事务内部。网络延迟会阻塞同数据库的其他写入。现已改为先读取版本和可见状态、在事务外调用模型、获得写锁后再次检查幂等键与版本，再解析同一版本状态并提交。并发变化会明确返回版本冲突。

### 已修正：模型可能从可见出口中猜测“那边”

首轮真实冒烟中，非思考模型把“我去那边”高置信度猜成某个合法出口。现在提示词明确禁止这种猜测，领域校验也会拒绝没有名称或标签锚点的模糊指代，确保“目标合法”不等于“玩家确实指向它”。

### 模式结论：思考模式不应无条件开启

同一批短意图测试中，思考模式延迟更高，并出现一次不存在的调查交互 ID；非思考模式在加固歧义规则后通过 8/8。系统保留思考开关，但默认值必须由固定评估决定，不能凭模型模式名称决定。

### 本轮执行错误：一次思考模式评估被重复调用

首次思考模式评估超过命令的直接等待时间后，运行会话编号没有被保留；进程已经完成，但结果无法取回，因此同一组 8 项评估被重新执行了一次。这没有修改游戏状态或泄漏密钥，但产生了不必要的模型费用。后续所有可能超过直接等待时间的付费评估必须从启动时就保留会话编号，并通过该编号继续读取输出，禁止因输出丢失盲目重跑。

### 已修正：合法目标列表会诱使模型强行映射

32 项评估首次运行时，模型把玩家明确说出的“王宫”映射成可见的栎木街。仅校验“输出目标是否合法”无法证明玩家提到了该目标。现在移动候选还必须由原文中的地点名称、别名或同首字的小范围错字支持；否则即使出口合法也会降级。

### 已修正：唯一可用交互会诱使模型猜代词

“我问问她”曾被猜成向玛莎询问债务，因为她是唯一有配置话题的 NPC。现在询问和定向发言必须由原文中的角色名称或别名支持。可用交互唯一不等于玩家指代唯一。

### 已修正：群体发言没有权威听众

模型把“大家先冷静”指向哈维，后端去掉错误目标后又把它当成无人听见。现在候选只声明 `audience=room`，规则引擎根据权威角色位置计算同场听众；模型不能自行列出监听者。

### 评估纪律：区分模型错误、规则错误与评分错误

首次 32 项结果为 22/32，其中部分失败是评分器漏算说话耗时，不应误报为安全事件。修正时分别记录模型语义错误、领域校验缺口、规则行为和评估预期，不能为了提高通过率直接放宽安全门槛。

## 7. 阶段 4B 第一部分自审

### 已修正：把完整投影交给叙述模型会泄漏 GM 信息

叙述上下文现在只包含结果代码、公开场景、公开时间、规则结果文本和玩家可见变化。玩家原话、事件载荷、完整投影、未发现出口和 GM 事实不进入请求。后端另行构造私有隐藏词典检查输出，词典本身也不发送给模型。

### 已修正：结构合法的叙述仍可能删掉确认结果

仅让模型声明 `supported_fact_ids` 无法证明它真的写出了对应事实，真实联调也证明即使提示词要求逐字保留，模型仍可能在句中插入氛围。当前协议因此只允许模型返回前后两个短氛围字段，由 Python 把必需事实原文拼在中间，并把额外氛围限制在 160 字以内。这牺牲了一部分文风自由，但从结构上阻止模型删改确认结果。

### 已修正：叙述模型可能偷偷提出事件或推进多个节拍

Narration Proposal 的 `proposed_events` 必须为空，`beat_count` 固定为 1，`returns_control` 固定为真。第一版曾保守拒绝顺序连接词；Narrative Plan 落地后允许“然后”“随后”连接计划内微动作，但仍拒绝计划外结果、风险、玩家决定和第二个主要节拍。即使文字声称发生变化，它也没有任何写状态通道。

### 已修正：叙述网络调用可能重新占用写锁

规则结算和叙述调用都已移到写事务之前；提交时重新检查幂等键与状态版本。自动测试在叙述适配器运行期间另开连接成功取得 `BEGIN IMMEDIATE`，证明模型等待没有占用 SQLite 写锁。

### 已修正：原始叙述输出可能通过调试接口外泄

请求与响应保留在后端私有 `narration_attempts` 审计中，普通回合详情固定返回 `null` 载荷，只暴露模型、采用状态、失败代码、令牌和延迟。审计不是世界事件，也不参与投影或记忆。

### 剩余风险：短自由文本仍无法得到形式化语义证明

四字隐藏片段扫描、逐字事实锚点和短扩展能显著降低风险，但不能证明所有新增修辞都没有隐含新事实。下一步必须用版本化叙述评估集测量真实模型，未达标前不放宽逐字锚点。

### 本轮修正：真实模型暴露了两处提示协议缺陷

第一版 JSON 示例把置信度写成 `0.0`，模型完全合规却照抄低值；改成高值后，模型又在“逐字保留”的结果句中间插入氛围。两次输出都被校验器拒绝，未污染状态。最终没有继续堆提示词，而是把候选改成前后氛围字段，由 Python 负责拼接确认事实，从结构上移除模型改写事实的能力。

### 新的产品校准：单节拍不能退化成碎片化问答

早期为防止 AI 一次推进过快，校验器对顺序连接词采取了保守拒绝。这只能作为安全基线，不能成为最终小说体验：走动、推门、落座和直接环境反馈如果都要求玩家确认，会造成过多操作。下一版要用 Narrative Plan 区分“微动作”和“主要剧情节拍”，允许一轮形成数个连贯段落，但在风险、代价、重大线索、承诺、不可逆行为和新主要场景前停下。

### 新的剧本边界：符合主线不等于固定路线

《灰港》的世界真相、人物动机、已发生事件和主线危机是核心锚点；线索来源、解决手段、场景顺序和支线出现方式属于可重排软节拍。玩家策略造成的新关系与后果可以成为原稿没有逐句写出的分支，但必须由权威事件产生并继续受核心因果约束。后续不能用“符合剧本”为名忽略玩家策略，也不能用“自由生成”为名抛弃剧本大致流程。

## 8. 阶段 4B 第二部分 Narrative Plan 自审

### 已修正：占位符协议仍依赖模型自觉

最初的多段落提案要求模型保留权威原子的文本占位符。真实 DeepSeek 会把占位符替换成它认为对应的正文，后端正确以 `required_atom_count_invalid` 拒绝，状态没有污染，但说明协议仍把安全寄托在提示遵循上。现改为 Proposal v3：模型只返回原子 ID、段落编号和连接文字，Python 插入权威原文，从结构上消除替换占位符的路径。

### 已修正：剧本边界只是提示文本，不能重放

核心锚点和停止位置如果只写进系统提示，既不能随场景版本审计，也无法证明存档当时使用哪套边界。剧本包 v5 现在要求每个场景提供 `narrativeGuidance`，并通过 `scene.started` v2 进入事件重放投影。旧 v1 事件仍可重放，未知版本明确拒绝。

### 已修正：玩家安全指引可能由作者误写成秘密提示

仅把字段命名为“玩家安全”没有约束力。加载器现在会把指引与 GM 事实、秘密条件、隐藏出口、人物私密材料和组织私密目标对照；命中时拒绝整个剧本包。运行时仍保留隐藏词与中文片段扫描，形成生成前和生成后的两层防护。

### 已修正：模型失败时又退回碎片化单句

确定性降级现在也读取 Narrative Plan，输出场景、微动作/确认结果和决策边界组成的多段落文本。关闭模型、超时、低置信度或安全拒绝不会改变状态，也不会迫使玩家回到“一句结果一次询问”的体验。

### 当前残余风险：计划模板仍不等于导演系统

当前微动作和决策边界主要按动作与结果类型生成，尚未根据完整场景阶段、NPC 意愿、风险等级和长期后果动态规划。它已经约束叙述表达，但不能替代阶段 7 的剧情导演。下一步应先以版本化评估集量化事实、泄漏、控制权、节拍、沉浸感和碎片化，再扩展模板。

## 9. 阶段 4C 混合 NPC 决策自审

### 已纠正：把人物判断误解成纯条件计算

最初实现方向容易继续扩展成“薪资 + 贪婪 - 原则”的固定总分。这能约束结果，却会让人物缺少上下文理解，也无法自然处理关系、风险、过去帮助和冲突动机。现已改为：Python 只提供有来源事实与不可越过的边界，AI 在受控 Schema 中综合选择，确认决定再由 Python 转成事件。人物档案是上下文，不是最终公式。

### 已修正：AI 引用全部字段导致合法意图降级

首次真实 DeepSeek 冒烟中，模型正确选择拒绝，但把上下文中 18 个因素全部列入 `cited_factor_ids`，超过 Schema 的 12 项上限，系统安全降级。根因是提示只写“至少两个”，没有说明上限和相关性要求。协议现明确要求 2～12 个最重要因素且不要罗列全部，并增加截断和非 JSON 响应测试。该次失败没有转移物品或执行请求。

### 已修正：安全降级可能绕过硬底线

早期降级逻辑只检查剧本声明的礼物偏好，没有同时读取本轮 `allowed_decisions`。如果未来目标没有接收容器或物品带有 NPC 拒绝的失窃标签，降级路径可能错误接受。现在任何降级接受都必须首先确认 `accept` 仍在允许集合中。

### 已修正：收下贿赂可能被误读为请求成功

贿赂事件和附带请求已经分开。`bribe.accepted` 只允许与真实 `item.transferred` 一起证明物品被收下，不能生成 `request.accepted`、钥匙转移、放行或秘密发现。叙述确认文本也明确保留这一边界。

### 当前残余风险：精确历史还不等于完整长期记忆

当前 NPC 决策能读取关系来源和已接受赠礼等确凿历史，已经证明上下文会影响本轮判断，但还不能从数百回合中检索承诺、欺骗模式、传闻和语义相近事件。阶段 5 必须在不降低来源校验的前提下增加混合检索、冲突消解、Token 预算和 Retrieval Trace。

### 已解决：真实人物决策质量尚未形成评估基线

现已建立 11 项《灰港》固定用例和 5 组成对比较，覆盖高低价值、关系变化、重复送礼、硬底线、风险变化和虚构历史。首轮校准发现模型引用了真实赠礼却忽略非零关系；系统没有降低评分标准，而是压缩零关系字段并提高动态历史优先级。完整真实基线达到 11/11、5/5、零泄漏和零危险副作用。

### 已修正：静态人物档案会淹没动态关系

最初上下文发送全部六个关系维度，即使值为零，也始终发送空的硬底线字段。真实模型容易把有限引用名额用于整张人物档案。现在只展开非零关系，零关系压缩为 `relationship_baseline`，空底线省略；同时人物职业、动机、恐惧和行为边界进入私有决策上下文，使人物判断既不退化成数字，也不会忽略运行中历史。

### 已修正：回合详情缺少长期记忆追踪导致网页崩溃

真实玩家回合首次通过网页提交后，后端服务层已经生成 `retrieval_traces` 和
`scene_memory_summaries`，但 FastAPI 的 `TurnDetailResponse` 没有声明这两个字段，
响应序列化后前端直接访问 `retrieval_traces[0]` 会触发运行时错误。现在 API schema
显式返回两类不含私密正文的元数据，前端还会把旧服务或缺字段响应归一化为空数组。
这保持了后端审计边界，也让开发追踪在模型未触发记忆检索时稳定显示。

### 真实玩家联调结论

使用隔离存档完成 DeepSeek 驱动的查看通知、核对账本、移动、等待、询问、虚构历史
和贿赂回合。意图解析、叙述和 NPC 决策均在事务外调用；模型接受的 NPC 贿赂决定仍
被 Python 的物品、位置、风险和后果规则拒绝，刀没有离开玩家背包。重复幂等键没有
重复事件，旧状态版本返回 409，重启后状态版本、世界时间、地点和物品保持一致。
网页提交同一流程后无新的控制台错误，开发追踪能看到模型审计与来源链。

### 当前残余风险：直接 API 调用仍应明确角色 ID

《灰港》剧本的玩家角色 ID 是 `protagonist`，网页会从状态读取并发送该 ID；省略
`actor_id` 的手工 API 请求会使用通用占位值 `player`，模型上下文因此安全降级为本地
解析。它不会污染状态，但 API 示例和客户端契约仍应在后续统一为从剧本 manifest
派生玩家角色，而不是依赖默认占位值。

## 10. 以后每轮开发前后的固定自审

开发前：

1. 搜索演示角色、物品、地点和容器 ID；
2. 确认默认策略不会替玩家或 NPC 作决定；
3. 明确成功、拒绝、缺失、歧义和重复提交；
4. 确认内容属于剧本包、规则包还是运行中存档；
5. 先记录当前测试数量和覆盖率。

开发后：

1. 使用至少一组完全不同的 NPC、物品和容器验证通用性；
2. 验证剧本包版本兼容路径，不让历史产品夹具进入新规则核心；
3. 搜索剩余专用 ID 并逐一解释；
4. 验证失败路径没有事件和版本污染；
5. 重启真实本地服务后执行 HTTP 联调；
6. 完成后恢复可验收的演示初始状态；
7. 更新路线图、规范、验证报告和本自审文件。
