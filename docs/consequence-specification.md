# 后果传播规范

## 1. 目标

后果系统把过去事件转化为未来可验证的状态和判定条件，使玩家行为产生连续影响，而不是只作为 AI 的背景记忆。

## 2. 标准链路

```text
已提交事件
→ 领域效果规则
→ 更新直接投影
→ 生成需要传播的后续事件
→ 更新角色认知、关系、声望或法律状态
→ 后续判定读取仍有效的影响
```

记住一件事不等于这件事自动产生数值。只有已注册的后果规则才能改变权威投影。

## 3. 效果记录

可持续影响至少保存：

```json
{
  "effectId": "effect_01...",
  "effectType": "personal_debt",
  "subjectId": "guard_017",
  "objectId": "player",
  "scopeId": null,
  "value": 1,
  "sourceEventId": "evt_gift_accepted",
  "createdAtWorldTime": 39720,
  "expiresAtWorldTime": null,
  "status": "active"
}
```

不同效果可以使用专用数据结构，但都必须保留来源、作用对象、范围、有效时间和当前状态。

## 4. 作用范围

效果必须明确属于以下一种或多种范围：

- 个人：特定 NPC 对特定身份；
- 阵营：组织成员共享的正式评价；
- 地区：某地区内传播的公众名声；
- 法律管辖：特定政权可执行的嫌疑或通缉；
- 世界级：极少数广泛传播的身份标签。

个人目击不能自动升级为全地区事实。升级必须经过报告、证据、传播或制度处理事件。

## 5. 关系效果

第一版关系维度：

```text
favor
trust
fear
respect
suspicion
debt
```

关系变化取决于事件语义和 NPC 特征。例如接受昂贵礼物可能增加好感，也可能因为廉洁性增加怀疑。具体规则输出必须说明：

- 改变了哪个维度；
- 改变量或等级；
- 来源事件；
- 适用的 NPC 特征规则；
- 是否存在期限或偿还条件。

人情被使用后应通过正式事件结算，不能仅把数值静默归零。

## 6. 行动判定中的影响装配

一次请求判定按顺序收集：

1. 行动本身的基础难度或许可条件；
2. 物品、地点和职位约束；
3. 目标 NPC 的目标、原则和当前状态；
4. 双方关系及其有效来源；
5. 适用声望、法律和身份暴露；
6. 当前场合、见证者和风险；
7. 骰子或规则体系要求的随机因素。

判定结果应返回可审计原因：

```json
{
  "outcomeTier": "refuse_but_offer_alternative",
  "reasons": [
    {"code": "restricted_item", "value": 25},
    {"code": "institutional_loyalty", "value": 20},
    {"code": "personal_debt", "value": -15, "sourceEventId": "evt_gift_accepted"}
  ]
}
```

玩家界面可以只展示自然语言原因，开发者界面必须保留完整原因。

## 7. 信息传播与通缉

犯罪后果不能直接从“犯罪发生”跳到“所有人敌对”。最小传播链：

```text
crime.committed
→ witness.observed
→ information.reported
→ evidence.registered
→ suspect.identified 或 suspect.described
→ wanted.issued
→ notice.received
→ recognition.succeeded
→ npc.response_decided
```

每一步都可能失败、延迟或携带错误信息。NPC 只有收到通缉信息并识别玩家后，才能把通缉用于当前反应。

## 8. 时间与衰减

效果可以：

- 永久保留；
- 在明确时间到期；
- 被其他事件消费；
- 随时间分段衰减；
- 因赦免、澄清或反证失效。

重大事件不应简单按天线性遗忘。衰减策略属于规则配置，并以世界时间计算。

## 9. 重复行为与人物印象

“守信”“慷慨”“惯于暴力”等长期印象只能由多个可追溯事件经过规则聚合形成。印象记录必须包含证据事件集合和置信度，单次行为默认不定义人格。

## 10. 赠酒与钥匙基准案例

正确链路：

```text
玩家确实持有酒
→ 守卫接受赠礼
→ 物品转移
→ 关系效果产生并引用赠礼事件
→ 两天后玩家请求钥匙
→ 判定读取未偿还人情和守卫职责
→ 结果为拒绝钥匙但提供替代信息
```

禁止的捷径：

- 仅因玩家声称送过酒就创建关系效果；
- 仅因检索到叙述文本就增加好感；
- 好感足够高便绕过物品安全级别；
- 守卫不知道通缉却按通缉犯对待玩家；
- AI 在叙述中交出钥匙但不创建物品转移。
