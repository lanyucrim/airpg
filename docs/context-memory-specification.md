# 上下文与记忆规范

## 1. 目标

记忆系统的职责不是“把过去聊天尽量塞给 AI”，而是为当前步骤提供正确、相关、权限允许且可追溯的信息。

## 2. 记忆层级

| 层级 | 内容 | 是否权威 | 主要查询方式 |
|---|---|---:|---|
| 原始消息 | 玩家与叙述器逐字原文 | 只对“谁说过什么”权威 | 回合、说话者、时间查询 |
| 当前场景 | 地点、参与者、可见物、刚发生的事件 | 部分来自投影 | 精确查询 |
| 当前状态 | 背包、关系、时间、法律状态、时钟 | 是 | 精确查询 |
| 事件历史 | 已发生事件及因果链 | 是 | 实体、类型、时间查询 |
| 角色认知 | 某角色知道、相信或怀疑的事实 | 对该角色决策权威 | 角色与命题查询 |
| 剧情状态 | 未解决承诺、线索、计划和危机时钟 | 是 | 状态与标签查询 |
| 长期摘要 | 场景或章节压缩结果 | 否 | 时间和主题查询 |
| 叙事原文 | 玩家曾看到的描述和对话 | 否 | 全文或语义查询 |

摘要和叙事原文只能帮助表达，不能覆盖事件和投影。

“原始消息是 Ground Truth”只表示它能证明某句话确实被说过，不表示这句话描述的世界事实成立。玩家说“我拿到了钥匙”和叙述器错误地写“钥匙已经到手”都必须保留原文，但只有经过校验的事件才能改变钥匙归属。

## 3. 上下文装配顺序

每次装配必须先确定调用者、任务和可见范围，再按以下顺序获取信息：

1. 回合、场景和参与者标识；
2. 当前权威状态；
3. 当前行动直接引用的实体；
4. 与这些实体相关的未解决效果和来源事件；
5. 调用者允许使用的角色认知；
6. 活跃剧情线、时钟和转场约束；
7. 近期重要事件；
8. 语义相似的摘要或叙事片段。

如果预算不足，从第 8 项开始裁剪，不能裁掉决定判定所需的权威状态。

## 4. 不同 AI 角色使用不同视图

### 意图解析视图

只需要玩家原文、当前可引用实体和必要对话上下文。不得提供隐藏世界秘密。

### 导演视图

可以读取世界秘密、NPC 目标和允许结果，但必须明确标记哪些内容不可向玩家泄露。

### NPC 决策视图

只能读取该 NPC 的属性、目标、关系和认知。世界真相只有在 NPC 知道时才能进入此视图。AI 负责综合这些可能相互冲突的因素；Python 负责确认上下文来源、硬约束、允许后果和事件提交，而不是用单一阈值替代人物判断。

当前 `offer_item` 纵向切片已经把真实物品归属、双方位置、物品价值、NPC 决策档案、六维关系及其来源、经过角色作用域与时间检查的情节记忆送入该视图。`NpcDecisionContext v2` 中的记忆都绑定唯一来源事件；模型只能返回接受、拒绝、还价、延迟或试探，并引用上下文内的事实与记忆。玩家自行声称“以前送过”不会生成记忆；接受物品也不等于相关请求已经完成。

### 叙述视图

只包含已提交事件和玩家可感知结果。不能包含未揭示的导演信息。

## 5. 相关历史的确定性检索

历史影响首先通过明确关联获得：

```text
当前目标 NPC
→ 双方关系的来源事件
→ 未偿还人情
→ 与当前行动类型相符的承诺、赠礼、威胁或欺骗
→ 仍有效的地区、阵营和法律影响
```

“前天送酒”应通过 `targetId + eventType + itemId/definitionId + worldTime` 检索，而不是仅依赖文本相似度。

阶段 5A～5B 已把这些事件投影成可重建的 `episodic_memories v2`，先按实体生成候选，再检查角色作用域、时间、事件类型和上下文预算，并记录不含私密正文的 Retrieval Trace。位置变化通过 `updates` 保留新旧时间链，关系变化通过 `caused_by` 指向造成它的真实互动；旧事实不会因更新而删除。未来全文或向量候选仍必须绑定来源事件并重做同一组检查，才能进入决策上下文。

场景摘要按 `scene + location segment` 生成，只组合已经锚定的情节记忆，并保存事件序号范围、世界时间范围、全部来源事件、生成器版本以及未解决目标。摘要可以丢弃重建，不能成为位置、关系或物品的权威来源。

## 6. 摘要规则

摘要必须：

- 保存覆盖的事件序号范围；
- 列出引用的重要事件编号；
- 区分已解决和未解决事项；
- 标明生成器和版本；
- 允许丢弃后重新生成。

摘要不得直接产生关系、声望、物品或法律变化。发现摘要与权威数据冲突时，忽略摘要并记录质量问题。

## 7. 记忆重要度与衰减

是否保留长期记忆由规则决定，不由叙述模型随意决定。重要度考虑：

- 是否改变权威状态；
- 是否形成承诺、债务、秘密或敌意；
- 是否影响活跃剧情线；
- 是否被关键角色目击；
- 是否重复发生并形成行为印象；
- 是否具有明确期限。

琐碎叙事细节可以从活动上下文中淘汰；来源事件仍保留在事件日志中。

## 8. 记忆污染防护

- 玩家对历史的声称不能直接写入历史摘要；
- AI 新增的重要设定必须先通过正式创建事件；
- 角色的错误信念必须明确标记为信念，不写成世界事实；
- 检索结果必须携带来源类型和事件编号；
- 后续模型输出不能把“可能”“怀疑”自动改写为“确定”。

## 9. 可观测性

开发者应能查看每次 AI 调用的上下文清单，包括：

- 信息来源；
- 权威等级；
- 所属角色视图；
- 被选择的原因；
- 被裁剪的内容；
- 最终上下文大小。
