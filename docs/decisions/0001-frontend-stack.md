# ADR-0001：前端采用 Next.js 与 TypeScript

状态：接受  
日期：2026-08-19

## 背景

后端确定使用 Python，并作为游戏规则、世界状态、数据库事务和 AI 协调的唯一权威服务。前端需要支持：

- 高交互的文字跑团界面；
- 背包、角色、地图、线索等多面板状态；
- 流式显示 AI 叙述；
- 开发者调试和回合审计页面；
- 将来可能存在的公开主页、战役分享页和搜索引擎可见内容。

## 决策

前端采用：

```text
Next.js
React
TypeScript
```

阶段 1 再决定具体稳定版本、样式方案、状态管理和组件库，并通过锁文件固定版本。

Next.js 只作为界面和页面组织层。所有游戏领域规则仍在 Python 后端执行。

## 前后端边界

前端可以：

- 展示后端返回的状态；
- 收集玩家输入；
- 维护纯界面状态；
- 显示流式叙述；
- 请求查询、提交命令和重新生成叙述。

前端不可以：

- 自行决定骰子结果；
- 修改物品所有权；
- 计算最终关系或通缉状态；
- 把 AI 文本直接当作状态；
- 在浏览器中保存权威存档。

前后端通过版本化接口通信。实时叙述优先使用单向流式协议；只有出现真正双向实时需求时再增加 WebSocket。

## 选择理由

- TypeScript 能为复杂界面和版本化接口提供静态类型检查；
- React 生态适合构建多面板、高交互和流式更新界面；
- Next.js 同时支持 SPA、静态输出和服务端渲染，早期可以保持简单，后期不必为公开页面重新迁移框架；
- 路由、布局、错误边界和构建约定较完整，适合长期项目；
- Python 后端保持唯一权威，避免形成两套业务逻辑。

## 代价

- 项目需要同时维护 Python 与 Node.js 两套运行环境；
- Next.js 的服务端能力可能与 Python 后端产生职责重叠；
- 团队必须主动禁止将游戏规则写入 Server Actions 或 Route Handlers；
- 若项目最终只是纯客户端工具，Next.js 会比 React + Vite 更重。

## 被考虑的替代方案

### React + Vite

优点是轻量、职责简单，非常适合纯客户端应用。未选择的主要原因是项目未来可能需要公开内容、服务端渲染和更完整的页面约定。若确认永远只做登录后的纯客户端游戏，可重新评估此决策。

### Vue / Nuxt

开发体验良好，但当前没有足以抵消 React 生态和团队长期招聘、组件选择优势的特定需求。

### SvelteKit

界面代码简洁，但大型长期项目的生态覆盖和团队可替代性不是当前的优先选择。

## 复审条件

出现以下任一情况时复审：

- 明确只需要纯客户端应用且无需任何服务端页面能力；
- 团队主要技术能力集中在 Vue 或 Svelte；
- 部署环境无法承载 Node.js，且静态输出不能满足需求；
- Next.js 服务端边界持续造成与 Python 后端的职责混乱。
