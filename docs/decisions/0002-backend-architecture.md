# ADR-0002：Python 模块化单体与事件驱动内核

状态：接受  
日期：2026-08-19

## 背景

一次游戏回合可能同时改变物品、时间、关系、认知、法律状态和剧情时钟。这些变化需要强一致提交，同时需要允许 AI 调用失败和叙述重试。

## 决策

- 后端使用 Python；
- 第一版采用模块化单体，不拆分微服务；
- 以追加式事件作为重要事实记录；
- 使用状态投影提供当前查询；
- 以单个战役回合为主要事务边界；
- AI 接入通过独立边界模块，不渗透到领域对象；
- Web 框架、数据库产品和 Python 具体版本在阶段 1 决定。

## 分层

```text
接口层：HTTP、流式响应、身份与输入格式
应用层：回合协调、事务、幂等和权限
领域层：物品、关系、认知、法律、场景和规则
基础设施层：数据库、模型 SDK、缓存和日志
```

领域层不能依赖具体网页框架、数据库客户端或模型 SDK。应用层通过接口调用基础设施实现。

## 原因

- 单次回合跨多个领域，单体事务最容易保证一致性；
- Python 适合规则实现、AI 接入和测试工具；
- 模块边界清晰后，未来可独立拆出高成本的 AI 或检索模块；
- 事件日志支持审计、回放、存档修复和叙述重生成。

## 代价

- 事件结构和投影器需要严格版本管理；
- 读取当前状态时不能每次完整重放，后期需要快照或持久化投影；
- 团队必须避免模块之间直接读取并修改内部数据；
- 事件驱动不能取代合理的关系数据库模型。

## 暂不拆分微服务的条件

只有出现明确证据时才考虑拆分，例如：

- AI 调用需要独立扩缩容；
- 检索工作负载影响核心事务；
- 多个团队需要独立发布；
- 单体部署出现无法通过模块优化解决的容量瓶颈。
