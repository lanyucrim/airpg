# ADR 0010：Narrative Plan 与剧本包 v5 叙事边界

状态：已接受  
日期：2026-08-20

## 背景

阶段 4B 第一版只允许模型在确认结果前后增加短氛围，安全但过于碎片化，无法形成小说式多段落体验。直接让模型自由续写又会带来三个问题：改写规则结果、提前泄漏剧本秘密，以及替玩家跨过新的风险或重大决定。

真实 DeepSeek 联调还表明，即使提示要求保留占位符，模型也可能把占位符替换成正文。仅依赖提示词不能保证权威事实不被修改。

## 决策

1. Python 在规则结算后构造 `NarrativePlan` v1，按顺序列出场景锚点、低风险微动作、确认结果、可见变化和决策边界。
2. 每个权威叙事原子保存稳定 ID 和原文；模型不返回原子正文。
3. `NarrationProposal` v3 只返回原子所在段落及原子前后的连接文字。Python 校验后插入原文并组装 2～5 个段落。
4. 每轮可以连续描写多个计划内微动作，但 `beat_count` 固定为 1，最后一个必需原子必须是玩家决策边界。
5. 剧本包 v5 要求每个场景提供 `narrativeGuidance`：玩家安全前提、硬锚点、灵活策略和停止边界。
6. 剧本加载器拒绝在叙事指引中出现 GM 事实、秘密条件、隐藏出口、人物私密材料或组织私密目标。
7. v5 使用 `scene.started` 事件版本 2 保存指引；投影器继续兼容版本 1，并明确拒绝未知版本。
8. 模型调用继续位于 SQLite 写事务之外；任何结构、领域或安全校验失败都使用同一计划的确定性多段落叙述，不影响权威事件。

## 影响

正面影响：

- 叙述可以自然连接走动、开门、观察等微动作，不需要每一步都询问玩家；
- 模型无法删除、重排或改写确认结果；
- 《灰港》的主线危机与玩家策略边界进入可版本化、可重放结构；
- 模型失败仍能返回可读的多段落结果。

代价与限制：

- 当前微动作和决策边界仍由动作类型模板生成，表达范围有限；
- 连接文字仍是自由文本，只能通过保守校验和评估降低语义风险；
- v5 内容作者必须逐场景维护玩家安全指引；
- 扩大模型自由度前必须先建立版本化叙述评估基线。

## 被否决的方案

- 让模型直接返回完整叙述：无法从结构上保证确认事实不被改写。
- 让模型原样保留文本占位符：真实模型会主动替换占位符，协议不可靠。
- 继续只允许前后短氛围：安全但无法满足连续、沉浸、少打断的产品目标。
- 用固定剧情脚本代替计划：会忽略玩家策略和运行中事件造成的合理分支。
