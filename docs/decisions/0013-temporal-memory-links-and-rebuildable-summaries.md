# ADR 0013：保留旧事实的时间链接与可重建场景摘要

状态：已接受  
日期：2026-08-20

## 背景

阶段 5A 已经保证情节记忆锚定确认事件，并经过实体、时间和角色作用域检查。但单条记忆仍不足以表达三种常见关系：

1. 新事件改变了同一状态，例如角色从大厅移动到厨房；
2. 一个结果由另一事件造成，例如接受礼物导致关系变化；
3. 长场景包含许多事件，模型需要较短但仍可追溯的概览。

直接覆盖旧记忆会破坏“过去在哪里”“何时改变”的问题；让 AI 自由总结又可能加入未发生事实或丢失来源。

## 研究依据

- [THEANINE](https://aclanthology.org/2025.naacl-long.435/) 强调保留旧记忆并通过时间与因果结构组织更新，而不是只保存最新文本。
- [A-MEM](https://arxiv.org/abs/2502.12110) 说明动态属性和记忆链接有助于形成可演化组织；本项目要求所有链接仍由事件字段或确定性状态槽产生。
- [RMM](https://aclanthology.org/2025.acl-long.413/) 使用多粒度记忆改善长对话检索；本项目先实现事件与场景片段两级，摘要仍必须回链完整事件。
- [LongMemEval](https://arxiv.org/abs/2410.10813) 把知识更新、时间推理和拒答视为独立能力，因此三者必须分别评估。
- [LoCoMo](https://arxiv.org/abs/2402.17753) 显示时间和因果问题不能仅靠文本相似度稳定解决，因此链接是结构化数据，而不是在 prompt 中临时猜测。

## 决策

1. 新增 `memory_links v1`，方向固定为“新记忆 → 相关旧记忆”。首期关系为：
   - `updates`：同一状态槽的新值接续旧值；
   - `caused_by`：当前记忆由目标记忆所锚定事件直接造成。
2. `character.moved` 进入情节记忆，使用 `character_location:<character_id>` 作为确定性更新槽。新位置记忆链接上一条同槽位置记忆，但旧记忆保持 `active`，因为它仍是有效历史。
3. `relationship.changed` 根据事件中的 `sourceEventId` 建立 `caused_by`。如果来源事件没有对应记忆，不虚构链接，也不阻止权威事件提交。
4. 链接必须带 `source_event_id`，且该事件必须是链接发起记忆的来源。模型、摘要或相似度不能直接新增链接。
5. “当前在哪里”继续查询当前投影；`updates` 链只用于历史顺序、更新解释和候选扩展，不成为第二套当前状态。
6. 新增 `scene_memory_summaries v1`。摘要按 `scene_id + location segment` 切分，保存事件序号范围、世界时间范围、生成器版本及全部来源事件。
7. 首期摘要由纯 Python 模板从已经投影的情节记忆组成，不调用 AI；空片段不保存，配置事件和纯时间推进不单独写入摘要。
8. 摘要是可重建读模型。重建时与情节记忆、链接一起在单个事务内替换，不能改变事件或当前投影。
9. 摘要只能参与候选选择和叙述背景，不能直接改变关系、位置、物品、知识、通缉或任务状态。
10. 建立版本化《灰港》长期记忆评估集，至少分开测量事实、时间、更新、因果、拒答、当前路由和 NPC 作用域。

## 影响

正面影响：

- 可以同时回答“以前在哪里”和“现在在哪里”，而不删除旧位置；
- 关系变化可以追溯到造成它的互动；
- 长场景可以先读取短摘要，再按来源展开事件；
- 摘要错误可以整体丢弃并重建；
- 引入全文或向量候选前已经有可量化基线。

代价与限制：

- 当前只为位置建立更新槽，物品所有权、通缉、任务和信念更新将在各自领域事件稳定后扩展；
- 场景片段以地点切换为边界，还不是完整的导演场景状态机；
- 确定性摘要表达较朴素，后续 AI 压缩仍要保留相同来源协议；
- 多跳检索首期只沿明确链接扩展一跳，不能自动把相似事件连成因果。

## 被否决的方案

- 新值出现时删除旧记忆：破坏历史时间问题。
- 把旧记忆标成无效并从所有查询排除：会把“过去曾成立”错误地变成从未发生。
- 由 embedding 相似度自动生成 `caused_by`：相似不是因果证据。
- 只保存最终场景摘要：一旦摘要出错就无法定位或重建。
- 每回合都调用 AI 重写整个场景摘要：成本随战役增长，也增加事实漂移。
