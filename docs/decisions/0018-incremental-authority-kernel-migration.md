# ADR 0018：权威内核的分阶段迁移与领域拆分

状态：已接受，待阶段 7.5B 实施

日期：2026-08-20

## 背景

阶段 1—7 为了尽快形成可玩的纵向切片，把回合协调、意图解析、环境搜索、物品操作、NPC 判定和事件投影集中在少数大文件中。当前 `engine.py`、`projection.py`、`scenario.py`、`npc_decision.py` 和网页主组件已经承担互相耦合的多个职责。直接在这些文件上继续增加 AI 日常、V4.2 主线状态机和统一物品生命周期，会使规则分支不可验证，也会威胁旧存档的重放能力。

## 决策

采用“端口先行、领域逐个切流、旧入口兼容、摘要对比验收”的迁移策略。

### 1. 先冻结四个权威端口

- `EventStore`：追加事件、幂等、版本冲突和查询；
- `CommandResolver`：把玩家输入解析为受约束的命令候选；
- `ProjectionRunner`：按事件版本重建当前状态；
- `NarrativeResult`：只接收确认结果和玩家可见变化。

端口是纯领域契约，不能依赖具体模型 SDK。SQLite 和 PostgreSQL 都必须实现同一契约。

### 2. 按领域迁移，不进行大爆炸式重写

迁移顺序固定为：

1. 内容编译与加载；
2. 回合协调和事件投影；
3. 环境机会与日常行动；
4. 物品、容器和交易；
5. NPC 决策与社会关系；
6. 世界自治与经济；
7. 网页公开状态与玩家操作。

每次只允许一个领域成为新实现的权威来源。旧入口保留兼容适配，但不能在适配层继续添加业务规则。

### 3. 每个领域的切流门槛

领域切流前必须同时满足：

- 旧事件、旧存档和重复命令的回放结果与新实现摘要一致；
- 成功、前置条件失败、无结果、部分成功、模型不可用和重复提交均有测试；
- 新实现不允许 AI 或前端直接写入投影；
- 新事件具备 `schemaVersion`、来源事件和幂等键；
- 网页玩家模式完成一次真实操作验收；
- 失败样本已经进入回归语料。

### 4. 兼容和回滚

- 旧事件通过显式版本适配器进入新投影，不删除或重写历史事件；
- 新旧投影同时运行时，只允许新投影提交结果，旧投影用于摘要对比；
- 摘要不一致时停止切流并保留旧入口，不能用新结果覆盖旧存档；
- 迁移失败可以回到上一个已验收领域，不需要回滚已经确认的事件。

## 后果

正面影响：

- 大文件会逐步缩小，领域规则可以离线单测；
- V4.2 内容、日常 AI 和统一物品拥有清晰的接入边界；
- 旧存档和阶段 5—7 的已确认事实继续可重放；
- 真实网页验收能定位是内容、规则、投影还是界面问题。

代价：

- 阶段 7.5B 是基础迁移阶段，耗时会高于单纯增加功能；
- 一段时间内会同时维护旧入口、兼容适配器和新领域模块；
- 每个领域都需要新旧摘要对比和回归测试，测试数量会显著增加。
