# DeepSeek 意图适配器

状态：本地真实模型纵向切片  
日期：2026-08-20

> 文档定位：历史适配器规范与当前能力基线，不是当前开发任务清单；当前开发模块和任务以 `docs/development.md` 为准。

## 目的

DeepSeek 只负责把玩家文本转成 `ModelIntentProposal` 候选。它不访问数据库、不提交事件、不决定行动成功，也不能绕过现有权威规则。

## 安全配置

- `TRPG_INTENT_MODEL_ENABLED` 默认 `false`；
- `DEEPSEEK_API_KEY` 只从后端进程环境读取；
- 密钥不进入源码、前端、SQLite、解析请求、审计记录或错误响应；
- 仅配置密钥而未显式启用时不会调用模型；
- 基础地址必须使用 HTTPS；
- 普通玩家接口只能看到模型名、状态、令牌和延迟，不能读取原始请求与输出。

可配置项完整列表见 `apps/server/.env.example`。

## 调用策略

- 默认模型：`deepseek-v4-flash`；
- 默认非思考模式；
- JSON Output；
- 温度为 0；
- 输出上限 900 tokens；
- 请求超时 20 秒；
- 只对 429、500、503 做最多一次重试；
- 任意失败进入现有本地解析器。

思考模式可通过 `DEEPSEEK_THINKING_MODE=enabled` 开启，并可设置推理强度。是否切换默认值必须由同一评估集的准确率、安全性和延迟共同决定。

## 事务边界

```text
读取当前版本与可见状态
        ↓
事务外调用 DeepSeek
        ↓
获得 SQLite 写锁
        ↓
再次检查幂等键与状态版本
        ↓
规则解析、事件提交与审计同事务完成
```

模型等待期间世界若已经变化，旧候选不会覆盖新状态。

## 状态接口

`GET /api/v1/system/intent-model` 只返回是否启用、提供方、模型和最低置信度，不返回密钥。
