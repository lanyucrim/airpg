## 如何使用本控制台

项目按同级模块开发，不按历史阶段顺序开发。当前焦点只说明本轮工作的范围，不表示其他模块必须等待，也不表示某模块已经整体完成。每次开始新的模块工作前，应在本文件明确：

1. 目标、边界和明确不做的事项；
2. 受影响模块、公共协议和资料来源；
3. 验收方式、冒烟测试范围及是否需要全量回归；
4. 已修复问题、仍存风险和需要用户决定的事项。

所有实现仍必须遵守 [核心原则](core-principles.md) 和仓库 `AGENTS.md`：后端事件与投影是唯一权威，玩家输入、AI 输出和叙述都只能提出候选，不能直接写状态。

## 代码仓库与发布规则

- GitHub 仓库：`git@github.com:lanyucrim/airpg.git`。
- 项目以 `G:\AI-TRPG` 为单一 Git 仓库根目录，后端、网页、内容资料、测试和正式文档一起版本化；不得保留会让网页代码变成独立仓库的嵌套 `.git`。
- 日常开发默认只进行本次改动的冒烟测试。每日准备上传时，先运行本文件所列当前开发模块及其直接公共依赖的全量回归；历史范围外模块不因“每日全量”被重新纳入，除非本文件切换范围或用户明确要求。
- 测试结束后先向用户报告通过项、失败项和未验证项。只有获得用户当日明确允许，才能提交并推送；不得设置无人确认的自动上传。
- 测试失败时默认不推送。若用户在了解失败后仍明确要求上传，提交说明和本文件验证记录必须如实注明失败范围。
- `.env`、API 密钥、数据库、日志、覆盖率文件和测试/构建缓存只能留在本地，不得提交到远程仓库。

## 当前批次

### 焦点：地点模块 LO-08

本轮已完成玩家出发前的天气移动时间预览：

- 后端在公开出口读模型中统一提供 `baseTravelMinutes`、`weatherDelayMinutes`、`estimatedTravelMinutes`、`weatherCondition` 和 `weatherConditionName`。
- 预览复用实际移动结算的地点归属、建筑入口解析、确认天气和取整规则；前端不复制天气倍率，也不能修改最终移动时间。
- 玩家左侧地点移动界面显示“基础时间 + 当前天气预计加时 = 预计总时间”。内部结构移动明确显示天气加时为 0；只有跨顶层地点移动应用当前确认天气。
- 原 `travelMinutes` 字段继续表示出口基础时间，避免破坏现有 API 调用方；最终权威时间仍由提交移动时生成的 schema 2 `character.moved` 事件记录。

本轮不增加天气影响种类，不修改倍率，不处理出发后天气突变，也不扩展交通工具、封路或候车规则。

### 历史焦点：地点模块 LO-09 / LO-10

本轮已完成地点结构访问和运行时 ID 的基础收束：

- 图册结构 `access` 已成为正式强类型字段，只允许 `public`、`private`、`hidden`；缺省值是 `public`。编译和移动不再根据中文名称、用途或未类型化 `model_extra` 猜测隐藏状态。
- `private` 仍是资料描述，不自动上锁，符合“除明确隐藏结构外，其余内部结构可进入”的冻结规则。
- 隐藏结构可显式绑定 `discoveryId`。未绑定发现定义的隐藏结构只物化为 GM 资料节点，不生成入口；若绑定，则发现定义必须存在且必须列出编译器生成的隐藏入口 ID。
- 剧本出口现在强制执行：`visible=false` 必须有 `discoveryId`，带 `discoveryId` 的出口必须是不可见出口；运行时入口同时保存相同发现 ID。
- 新增单一 `map/runtime_ids.py`，地点、结构、街道 ID 的当前输出和历史解析由该模块统一；编译器、公开地图、移动和家具不再各自维护 `RUNTIME_*` 表。
- 当前正式运行时 ID 规则保留开局资料已经发布的 `oak_street`、`red_mill_tavern`、白鹭屋和废弃面包房 ID；其余街道为 `atlas_street_<atlasStreetId>`，其余结构为 `atlas_room_<atlasStructureId>`。没有事件或资料来源的伪旧 ID `runtime_oak_street` 已删除，当前编译和读取均不接受。
- 建筑 shell 明确保留为地点聚合和街道入口节点，不是房间。玩家从街道进入建筑时，权威移动最终落到第一个非隐藏内部结构；旧命令仍可用建筑 ID 指定目的地。

本轮不新增发现剧情，不替 4 个尚无发现定义的隐藏结构杜撰线索、条件或揭示文本；这些结构在资料专题明确发现来源前保持不可进入。

### 历史焦点：地点/物品模块家具容器基础设计

本轮已完成家具容器的资料、AI 候选和运行时接入：

- 新增独立 `furniture-atlas.json` / `.md`，按灰港地图图册的 474 个真实内部结构生成 1-3 个固定家具容器，共 1422 条记录；街道、区域和城市不生成家具，明确隐藏结构的家具资料保留但对玩家不可见。
- 家具必须确实具备柜门、抽屉、箱体、格口、篮筐或其他收纳空间；长凳、普通桌子和开放式 `shelf` 不再作为家具容器类型。当前资料使用吧台、酒瓶柜、服务边柜、抽屉柜、药柜、器械柜、文件柜、锁箱、工具箱、零件柜、布草柜、衣帽柜、钥匙柜、收发柜、防雨户外柜等差异化类型。
- 程序种子描述会结合地点名称、结构用途、地点表面的时代材质和剧本资源描述生成；例如港口/铁路结构使用防潮漆与铆铁，医院使用便于擦拭的木材，银行/法院使用深色硬木与黄铜，隐藏结构仍不提升玩家可见性。
- 本次资料重生成替换了原先同质化的长凳、普通桌子和开放式 shelf；家具描述现在包含收纳方式、材质、地点用途和剧本地点背景，避免把没有内部空间的装饰家具当成容器。
- 家具资料归地点模块，家具的容量和物品放入/取出仍复用物品容器规则；家具不是 15 字段可携带物品。
- `ItemContainer` 增加家具名称、描述、类型、结构绑定、固定性和可见性字段；投影拒绝街道、非内部结构、错误结构绑定、非固定家具和非法容量。
- 开局编译将家具资料转换为 `container.created` 事件；AI、图册或前端不会直接写投影。
- 新增 DeepSeek 家具候选适配器和严格解析：每批最多 24 个结构，每个结构必须返回 1-3 个候选，程序校验类型、容量、结构覆盖和来源后才允许写图册。
- 当前生成资料使用程序种子（环境未配置 `DEEPSEEK_API_KEY`）；`scripts/generate_gray_harbor_furniture.py --ai` 可在配置密钥后按批生成模型候选，不会直接创建实例或事件。

本轮明确不做家具内容预置、家具破坏/拆除/移动、容器嵌套、家具开放/锁定和物品来源判定；这些仍由物品、行为、地点或事件专题决定。

### 历史焦点：物品模块 IT-06 初始耐久

本轮只实现物品创建时的初始耐久资料：

- 只有非消耗 `tool`、`clothing`、`equipment` 以及带装备子契约的实例使用耐久；一次性消耗品不使用耐久。
- `durability.current/max` 统一为 float；崭新的小刀固定为 `100.0/100.0` 标定基准。
- AI 根据名称、描述和明确状态词提出大类、状态、相对最大值和剩余比例；程序负责类别锁定、置信度、比例区间、类别上限和最终数值换算。
- 新 `item.created` 要求适用实例带初始耐久；历史 schema 3 创建事件只保留明确的回放分支。

本轮明确不设计腐坏、受潮、锈蚀时间演化、玩家行为扣耐久、维修或修理。物品模块只留下绝对耐久值校验接口；行为导致的损耗等事件语义等事件模块专题再决定。本轮不调用真实 AI，只验证隔离适配器和程序校验。

本轮可修复测试揭示的、无需新的架构决定且不会改变权威边界的明确缺陷。涉及事件语义、状态归属、AI 权限、游戏规则或玩家体验取舍的问题必须先登记到“待用户决策”，不得在验证过程中自行定义。

## 已冻结的决定

- **模块并列**：核心、地图与地点、人物、物品、行为、剧情、世界、AI、记忆、评估和网页按领域并列开发；当前焦点不是前后依赖顺序。
- **权威边界**：Python 后端通过经过校验的事件更新投影；AI、玩家输入、图册和叙述不能直接修改状态。
- **地图与地点**：七个大区仅为区域元数据；街道是无内部结构的通行层；普通及 `private` 地点结构默认开放，只有显式 `access=hidden` 的结构或带 `discoveryId` 的不可见出口使用发现门控；隐藏结构无发现绑定时不产生入口。内部移动不受天气加时，跨顶层地点才由地点模块叠加；玩家出发前由服务端公开同规则预计值。
- **人物**：能力和语言风格是带来源资料/运行时上下文，不是自动判定或 Canon 补全工具；未知信息保持空值或 `unknown`。
- **物品**：定义与实例分离；当前物品语义契约为 schema 7，耐久为 float，仅适用于非消耗工具、服装和装备实例。AI-物品只产生受限定义、参考、配方或初始耐久候选，不能凭空创建实例、获得来源或权威效果。
- **玩家货币**：玩家可用现金只由自有背包或其他自有容器中的 `currency` 实体实例构成；不保留数值账户/钱包余额。货币实例的总值仅按 `quantity * valueCrown` 派生；交易、找零、商户和银行账户不在当前范围。
- **AI**：模型只能产生结构化候选或叙述提案；`ai/platform` 不写状态，`ai/player` 不直接创建事件。真实调用必须可关闭、可审计并有程序降级。
- **家具容器**：家具属于地点内部结构资料，作为固定、不可携带的地点容器接入物品容量规则；每个真实内部结构必须有 1-3 个家具，街道/区域/城市不生成家具。家具图册独立于地点拓扑，AI 只返回候选，开局由确认的 `container.created` 事件物化。
- **清理与兼容**：删除无调用方的过期代码，不长期保留兼容门面；历史事件是否可回放由明确的核心兼容逻辑负责，不用旧业务文件掩盖。
- **验证成本**：普通模块批次默认只跑直接相关冒烟测试；只有核心公共协议或用户明确要求时才扩大范围。测试数字只记录对应批次范围，历史全仓库数字保留在历史归档。
