# 结构化意图解析规范

状态：阶段 4A 真实模型纵向切片  
日期：2026-08-20

> 文档定位：历史实现规范与当前能力基线，不是当前开发任务清单；当前开发模块和任务以 `docs/development.md` 为准。

## 1. 目的

AI 只负责把玩家自然语言转换成候选命令，不负责判定行动成功，也不能创建世界事实。模型输出和本地关键词解析最终都必须进入同一个 `ParsedCommand → resolve → Confirmed Events` 流程。

## 2. 输入边界

模型只允许看到：

- 玩家原始输入；
- 行动者 ID 与当前位置的公开名称；
- 当前地点可见角色；
- 玩家真实持有的物品；
- 玩家已发现且当前可见的出口；
- 后端当前允许的检查与询问交互；
- 允许输出的动作类型和最大动作数。

不得进入模型解析上下文：

- GM 事实；
- NPC 私密备注、秘密、恐惧和隐藏动机；
- 未发现出口；
- 其他角色的私人物品；
- 向量检索猜测；
- 尚未确认的玩家结果性声明。

## 3. 输出 Schema

模型输出 `ModelIntentProposal`：

```text
schema_version = 1
actions = 0～4 个 ModelActionCandidate
needs_clarification = true / false
confidence = 0～1
```

当前模型候选动作只允许：

```text
move
inspect_item
ask_topic
speak
wait
investigate_location
```

物品给予、请求等旧能力仍可由本地降级解析器处理；在完成更细的可见物品上下文前，不开放给模型猜测。

## 4. 双重校验

结构化输出并不等于权威结果。后端继续验证：

1. Pydantic 结构和枚举；
2. 置信度与澄清状态；
3. 目标是否属于当前可见角色；
4. 地点是否属于当前可见出口；
5. “那边”“那里”等无上下文锚点的指代是否被模型擅自猜成某个出口；
6. 调查交互是否由后端判定为可用；
7. 模型给出的目标是否与权威交互定义一致；
8. 等待时间是否在允许范围；
9. 复合动作是否超过场景节拍预算。

任一步失败都不能写入模型声称的事件。

## 5. Claim Scrubber

“我已经发现”“我成功说服”“我偷到了”等文字会被保留为 `claimed_outcome`，但命令仍表示一次尝试。规则引擎只提交自己允许的结果。

## 6. 降级与审计

解析来源分为：

- `local`：未启用模型，使用本地规则；
- `model`：模型 Schema 与领域校验均通过；
- `model_fallback`：模型超时、非法、低置信度、要求澄清或引用越权实体后，使用本地规则。

每回合都写入 `intent_attempts` 审计记录。模型请求和原始结构输出保存在后端数据库；普通玩家回合接口只返回状态、提供方、模型名、失败代码、令牌用量和延迟，不返回原始载荷，避免隐藏名称通过模型幻觉泄漏。

模型网络调用不得持有 SQLite 写事务。提交阶段必须重新检查幂等键和世界版本；如果调用期间世界已经变化，拒绝旧版本提交，不用模型结果覆盖新状态。

## 7. 当前边界

- 当前仓库已经完成 DeepSeek JSON 适配器、假模型测试和小规模真实模型冒烟评估；
- 真实模型默认关闭，只有后端显式启用且提供密钥时才会调用；
- DeepSeek 当前默认使用 `deepseek-v4-flash` 非思考模式；思考模式保留为可配置比较项，不因名称听起来更强就默认启用；
- 后续提供方仍必须实现同一 `ModelAdapter` 协议，不得改变规则引擎；
- 模型调用失败必须是可恢复情况，不能回滚已确认世界事实，也不能污染存档。
