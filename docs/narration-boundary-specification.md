# 安全 AI 叙述边界规范

状态：阶段 4B 第二部分首个纵向切片  
版本：2.0  
适用范围：回合结果叙述、模型适配器、审计、前端开发追踪

> 文档定位：历史实现规范与当前能力基线，不是当前开发任务清单；当前开发模块和任务以 `docs/development.md` 为准。

## 1. 目标

AI 叙述器只负责把 Python 规则已经确认的结果和可安全连续描写的微动作组织成小说式段落。它不是裁判，不解析新的玩家行动，不产生事件，也不修改投影。关闭模型、模型超时或任何校验失败时，系统使用同一份 Narrative Plan 生成确定性多段落叙述。

最终产品追求的是连续、缓慢展开的小说式沉浸感，而不是每完成一个无关紧要的小动作就把控制权弹回给玩家。这里的“缓慢”是指不跳过关键因果、人物反应和重要选择；不是把走几步、推门、落座、观察环境等自然连续动作拆成大量确认框。

当前实现已经引入 Narrative Plan，并允许一轮生成 2～5 个连贯段落。它仍然只是首个纵向切片：计划中的环境锚点、微动作、确认结果和决策边界由后端提供，模型只负责安排段落和补充不改变事实的感官连接文字。

## 2. 剧本约束与玩家自由

剧本内容分成三层，不能把“符合剧本”简单实现成固定台词或唯一通关路线：

### 2.1 不可随意改写的核心锚点

- 已建立的世界真相和历史；
- 主要人物在当前时刻的身份、知识、动机和已有承诺；
- 主线危机、倒计时、关键因果和已发生事件；
- 尚未被玩家行为实际改变的关键前置条件。

这些内容只能由明确规则事件改变，叙述不能为了顺畅自行改写。

### 2.2 可以重排的软剧情节拍

- 玩家从谁那里得到线索；
- 以调查、交易、威胁、欺骗或合作中的哪种策略解决问题；
- 场景发生的具体地点、顺序和时间；
- NPC 在不违背其认知与动机时采用的表达和应对方式；
- 可选冲突、支线人物和过渡场景是否出现。

软节拍允许根据玩家策略重排、延迟、替换或跳过，但必须保留可审计的因果关系。

### 2.3 由游玩产生的新内容

玩家建立的新关系、制造的新敌人、提出的新方案、暴露的新身份和改变的资源条件，可以形成剧本原稿没有逐句写出的合理分支。它们一旦通过规则校验，就以事件进入世界历史，并反过来约束后续剧情。

合理改编的标准是“从剧本人物、世界状态和玩家行为中可以推出”，而不是“AI 觉得这样更精彩”。

## 3. 一轮叙述应当推进多少

一轮默认可以包含多个微动作，但最多跨过一个需要玩家承担后果的主要剧情节拍。

可以自动连续描述的微动作包括：

- 完成玩家已经明确表达的动作所必需的走动、开门、落座和取放动作；
- 不产生额外风险或资源消耗的环境过渡；
- 已由规则确认的直接感官反馈；
- NPC 对已确认结果的即时、低风险表情和姿态反应；
- 为了段落自然所需的短时间连续过程。

必须停下来归还玩家控制权的决策边界包括：

- 即将承担新的明显风险、代价或资源消耗；
- 需要掷骰、战斗、追逐或高风险社交判定；
- 要作出承诺、交易、背叛、违法或不可逆选择；
- 出现足以改变当前策略的新线索或重大人物反应；
- 即将跨入新的主要场景或主要剧情节拍；
- 后续行动无法从玩家原始意图中合理推出。

因此，最终叙述通常应是数个连贯段落，而不是一句结果加一次询问；但结尾必须停在真正有意义的选择点。

## 4. 调用顺序

```text
玩家输入
→ 结构化命令
→ Python 规则结算
→ 确认的 Resolution / Events
→ Python 构造玩家安全的 Narrative Plan
→ 模型提出 Narration Proposal v3（原子位置与连接文字）
→ 结构、事实、秘密、节拍和控制权校验
→ Python 插入权威原子并组装段落，或使用确定性计划叙述
→ 原子提交消息、事件、审计和命令结果
```

模型调用必须位于 SQLite 写事务之外。取得写锁后，服务再次检查幂等键和状态版本；不一致时不得提交旧结果。

## 5. 模型可以看到的内容

- 动作类型；
- 结算状态与结果代码；
- 当前公开地点名称和公开时间标签；
- Narrative Plan 中经过筛选的剧本前提、硬锚点、可行策略与停止边界；
- 有稳定 ID 的公开场景锚点、微动作、确认结果、玩家可见变化和决策边界；
- 本轮主要剧情节拍预算与已结算数量；
- 文字长度上限。

模型不能看到玩家原始输入、原始事件载荷、完整投影、GM 事实、NPC 私密目标、未发现出口、秘密发现定义或向量检索结果。

剧本包 v5 强制每个场景提供 `narrativeGuidance`。加载时会拒绝包含 GM 事实、秘密条件、隐藏出口、人物私密材料或组织私密目标的指引，避免秘密在生成前就进入提示。

## 6. Narrative Plan v1

计划由 Python 构造，按以下顺序包含权威原子：

1. 当前公开场景与时间；
2. 玩家已明确行动所必需的低风险微动作；
3. 规则引擎的确认结果；
4. 已确认的玩家可见变化；
5. 本轮必须停下的有意义决策边界。

每个原子都有稳定 ID、类型、原文、是否必需和权威来源。计划还携带段落目标、主要节拍预算、剧本锚点与最大字符数。最后一个必需原子必须是 `decision_boundary`；模型不能调整原子顺序或增加原子。

## 7. Narration Proposal v3

候选必须是严格 JSON：

```json
{
  "schema_version": 3,
  "placements": [
    {
      "atom_id": "scene_anchor",
      "paragraph": 1,
      "prose_before": "雨声贴着窗格漫下来。",
      "prose_after": ""
    },
    {
      "atom_id": "confirmed_result",
      "paragraph": 2,
      "prose_before": "",
      "prose_after": "屋内的目光短暂地落到你身上。"
    },
    {
      "atom_id": "decision_boundary",
      "paragraph": 3,
      "prose_before": "",
      "prose_after": ""
    }
  ],
  "supported_atom_ids": [
    "scene_anchor",
    "confirmed_result",
    "decision_boundary"
  ],
  "beat_count": 1,
  "returns_control": true,
  "proposed_events": [],
  "confidence": 0.95
}
```

模型不提供任何权威原子正文，只提供原子所在段落和前后连接文字。Python 按计划插入原文，因此模型无法替换“实际发生了什么”。额外字段、未知或重复原子、非空 `proposed_events`、多个节拍或不归还玩家控制权都属于非法候选。

## 8. 采用条件

候选只有同时满足以下条件才可采用：

1. 通过 Pydantic 严格结构校验；
2. 置信度达到配置阈值；
3. 只引用计划中提供的原子 ID，并恰好覆盖每个必需原子一次；
4. 原子顺序与 Narrative Plan 完全一致；
5. 段落编号从 1 连续开始、不能回退，总数为 2～5；
6. `decision_boundary` 位于最后一段；
7. Python 先移除连接文字中对完整权威原文的重复，再检查其余文字不得虚构对话、发现、物品转移、状态变化或玩家决定；
8. 不包含尚未被角色获知的 GM 事实、秘密出口、秘密条件或私密目标的标识、原文及中文四字片段；
9. 不把规则拒绝的动作写成成功；
10. 最终文字由 Python 插入权威原子并组装，总长度不超过配置上限。

“然后”“随后”等连接词本身不再被一概拒绝，因为它们可以连接计划内微动作；真正被禁止的是计划外的新结果、新风险、新决定和第二个主要剧情节拍。

## 9. 审计与脱敏

每回合保存一条 `narration_attempts` 记录，包含提供方、模型、状态、失败代码、令牌、延迟以及后端私有的原始请求和响应。普通回合详情固定把原始载荷返回为 `null`，网页只显示采用、降级和计量摘要。

叙述审计不是世界事件，不进入投影，也不能成为长期记忆的权威来源。

## 10. 配置

- `TRPG_NARRATOR_MODEL_ENABLED`：默认 `false`；
- `TRPG_NARRATOR_MODEL_PROVIDER`：当前支持 `deepseek`；
- `TRPG_NARRATOR_MINIMUM_CONFIDENCE`：默认 `0.7`；
- `TRPG_NARRATOR_MAX_CHARACTERS`：默认 `1200`；
- `DEEPSEEK_NARRATOR_MODEL`：可覆盖共享模型名；
- `DEEPSEEK_NARRATOR_MAX_TOKENS`：可覆盖共享输出上限；
- `DEEPSEEK_NARRATOR_THINKING_MODE`：默认继承共享设置；
- `DEEPSEEK_NARRATOR_REASONING_EFFORT`：思考模式下使用。

仅配置密钥不会启用叙述模型，必须显式打开开关。

## 11. 下一步：版本化叙述评估

Narrative Plan 首个切片已经落地，下一步不再凭少量成功样本放宽生成权限，而是建立《灰港》固定评估集：

- 成功移动、失败移动、检查、询问、群体发言和复合行动；
- 不同玩家策略对同一剧本危机的合理分支；
- 事实逐字保留、隐藏信息零泄漏、失败不改成功；
- 玩家控制权、主要节拍越界、碎片化与沉浸感；
- 模型采用率、降级原因、P95 延迟和令牌成本。

只有版本化评估达到发布门槛后，才考虑扩大可用环境原子、NPC 即时反应类型或允许更自由的事实改写。

## 12. 当前残余风险

自由连接文字不存在仅靠 Schema 就能证明语义完全正确的方法。当前通过玩家安全计划、权威原子插入、剧本指引预检、隐藏片段扫描、语义风险词检查和确定性降级降低风险。现有微动作模板仍偏通用，决策边界也由结果类型映射；后续需要用评估数据扩展，而不是让模型自行决定新的剧情事实。
