# 阶段 4B Narrative Plan 验证报告

日期：2026-08-20  
范围：Narrative Plan v1、Narration Proposal v3、剧本包 v5、多段落网页显示与真实 DeepSeek 回归

## 1. 完成内容

- Python 根据确认结果构造有序叙事原子：场景起点、低风险微动作、确认结果、可见变化和最终决策边界；
- 单回合允许 2～5 个连贯段落和多个计划内微动作，但主要剧情节拍预算仍为 1；
- 模型只提交原子段落位置与连接文字，权威原文由 Python 插入；
- 精确重复的权威句、时间锚点和抵达句会被确定性去重；
- 对话、秘密、玩家决定、未确认发现、物品变化、失败改成功和计划外事件仍会触发安全降级；
- 确定性降级也按同一计划输出多段落，不退回碎片化单句；
- 移动叙述从确认事件读取出发地和行动前时间，避免先写抵达再写出发；
- 剧本包升级到 schema v5 / 内容版本 0.5.0，每个场景必须提供玩家安全叙事指引；
- `scene.started` 升级到事件版本 2，投影器兼容旧版本 1 并拒绝未知版本；
- 加载器会拒绝把 GM 事实、秘密条件、隐藏出口、人物私密材料或组织私密目标写进叙事指引；
- 网页按空行显示多个故事段落，未复制后端叙事判定。

## 4. 联调中发现并修正的问题

1. 文本占位符会被模型主动替换：改为 Proposal v3，只让模型返回原子位置；
2. 模型偶尔完整复述权威句：由 Python 去重，不让重复文字造成整轮降级；
3. 移动计划最初使用结算后地点作为开头：改为从 `character.moved` 和 `time.advanced` 事件读取行动起点；
4. JSON 示例文案会被模型照抄：示例连接文字全部改为空字符串；
5. “你立刻”被一概视为抢夺控制权：改为只拒绝“立刻转身、离开、追上”等实际代替玩家行动的组合，感官反馈不误杀；
6. 旧版 PowerShell 读取 UTF-8 中文脚本失败、当前终端没有 Node 路径：使用工作区运行时和当前 PowerShell 重新验证，没有修改业务代码规避环境问题。

所有真实联调失败都只影响是否采用模型文字，确认事件和投影始终正确；失败回合随后被重置，没有留在验收存档中。

## 5. 残余风险与下一步

连接文字仍可能生成不进入权威状态的装饰性环境细节。玩家之后提及这些文字时，仍不能因此把它们当作真实物品或地点事实。下一步建立版本化《灰港》叙述评估集，测量：

- 权威原子保留与重复率；
- GM 信息泄漏率；
- 玩家控制权与主要节拍越界率；
- 装饰性细节与剧本冲突率；
- 沉浸感、碎片化程度、采用率、P95 延迟和令牌成本。

在评估达标前，不扩大模型的事实改写权限。
