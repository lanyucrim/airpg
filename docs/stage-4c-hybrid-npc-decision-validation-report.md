# 阶段 4C 混合 NPC 决策验证报告

日期：2026-08-20  
范围：剧本包 v6、NPC 决策档案、物品价值、有来源上下文、DeepSeek 结构化决定、Python 复核、审计与网页追踪

## 1. 本轮目标

验证 NPC 不是由纯条件表决定，也不是由 AI 任意改写世界。目标链路为：AI 综合人物、关系、风险和历史提出决定；Python 只接受符合权威事实、记忆来源和允许后果的提案。

## 2. 已实现

- `NpcDecisionContext` v1 汇集物品所有权、位置、价值、标签、人物档案、请求风险、六维关系及来源、已确认赠礼和关系记忆；
- `NpcDecisionProposal` v1 限制为接受、拒绝、还价、延迟或试探，禁止模型直接产生事件；
- Python 校验硬事实、未知引用、虚构历史、人物底线、无价值贿赂、置信度和物品转移语义；
- 剧本包升级为 v6 / `0.6.0`，八名 NPC 获得私有决策档案，现有物品获得经济价值和标签；
- `character.created` v2 保存可重放档案，投影兼容 v1 并拒绝未知版本；
- 新增私有 `npc_decision_attempts` 审计，普通接口只返回采用状态、失败代码、令牌与延迟；
- 前端开发追踪显示人物决策是否被模型采用，不复制任何判定规则；
- 赠礼与贿赂分开；收下贿赂只转移真实物品，不执行附带请求。

状态改变命令覆盖：

- 成功接受并真实转移物品；
- 拒绝、还价、延迟、试探时保留物品；
- 不在场、缺少物品、没有接收容器和人物硬底线；
- AI 虚构记忆、未知事实、低质量结构和模型不可用；
- 相同幂等键重复提交只调用一次模型且不重复转移；
- 模型调用期间不持有 SQLite 写锁。

## 4. 真实 DeepSeek 联调

输入：玩家把自己的小刀递给哈维，并试图以此换取通融。

第一次冒烟：

- 模型选择拒绝，但列出 18 个因素；
- Schema 最多允许 12 个，系统以 `model_schema_invalid` 安全降级；
- 没有转移物品，也没有执行附带请求；
- 根因是提示只写了“至少两个”，未说明上限和相关性要求。

修正后冒烟：

- 决策审计状态：`model_accepted`；
- 模型：`deepseek-v4-flash`；
- 结果：`bribe_rejected`；
- 事件：`bribe.offered`、`bribe.rejected`、`time.advanced`；
- 小刀仍属于玩家；
- “通融”没有被当作已执行；
- 决策调用使用 1606 tokens，约 1786 ms；
- 普通回合接口中的原始请求和响应均为 `null`。

联调后战役已恢复到状态版本 1 的白鹭屋开局，网页返回 HTTP 200，人物决策模型状态接口显示已启用。

## 5. 已知边界

- 当前只对 `offer_item` 完成第一条混合人物决策链；
- 当前历史来自精确事件与关系来源，尚未接入数百回合规模的混合检索；
- 档案中的目标、秘密、承诺、说谎和错误信念还没有统一进入人物上下文；
- 通缉、目击、传闻和阵营态度传播仍属于阶段 6；
- 单次真实联调不能证明人物质量，需要固定评估集覆盖不同 NPC、报价、关系和风险。

## 6. 下一步

1. 建立版本化《灰港》NPC 决策评估集，分别测量结构通过率、引用正确率、人物一致性、延迟和令牌；
2. 进入阶段 5，增加有来源的结构化、全文和语义记忆候选以及 Retrieval Trace；
3. 把承诺、威胁、欺骗和信誉模式加入可验证记忆类型；
4. 随后扩展到请求物品、放行、隐瞒、交易和其他高风险 NPC 行为。
