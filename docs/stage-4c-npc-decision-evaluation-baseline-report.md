# 阶段 4C NPC 决策评估基线报告

日期：2026-08-20  
评估集：`gray-harbor-npc-decision` v1.0.0  
模型：`deepseek-v4-flash`，非思考模式

## 1. 目的

单次试玩无法证明 NPC 真的受到人物、关系、历史和风险影响。本基线把这些要求变成可重复运行的固定语料，用于发现模型、提示词、上下文装配或规则校验的回归。

评估只观察模型提案和确认结果，不会把测试中的“接受度排序”写入正式规则。游戏运行时仍由 AI 综合判断，Python 只维护事实与后果边界。

## 2. 语料范围

11 个《灰港》案例覆盖：

- 哈维面对低价值普通风险与高价值低风险贿赂；
- 相同高价值物品对应低风险和背叛组织的高风险请求；
- 哈维拥有真实赠礼、好感、信任和人情债时的反应；
- 玩家虚构“上周救过你”但事件历史为空；
- 艾达和奥蒂斯不可被普通利益越过的反贿赂底线；
- 高贪婪、高腐败开放度收账人面对高价值与零价值物品；
- 玛莎面对无条件实用赠礼，以及存在真实正向历史时的反应。

5 组成对比较验证：

- 更高价值且更低风险不会比低价值普通风险更不利；
- 真实正向历史不会让同一提议变得更不利；
- 高风险请求不会比相同低风险请求更容易被接受；
- 高价值物品相对零价值物品产生更高接受倾向；
- 玛莎的真实正向历史不会降低她对相同赠礼的接受倾向。

`reject < delay < test < counteroffer < accept` 只用于评估相对变化，不是运行时人物公式，也不进入事件或投影。

## 3. 首轮校准发现

首批 4 个真实样本通过 3 个。哈维正向历史样本中，模型引用了真实赠礼记忆，却把 12 个因素名额主要用于静态人物档案，没有引用非零好感、信任和人情债。

原因不是历史缺失，而是上下文注意力分配不合理：六个关系维度即使为零也全部发送，人物档案又占据大量候选。

修正：

- 零关系压缩为一个 `relationship_baseline`；
- 只为非零关系保留独立事实和来源事件；
- 没有硬底线时不发送空 `profile_hard_refusals`；
- 提示明确优先引用发生变化的关系、来源历史、物品价值和请求风险；
- 补充人物职业、动机、恐惧和剧本行为边界，减少纯数值化人物判断。

修正后单项复测通过，随后运行完整基线。

## 5. 自动验证

评估器自身覆盖：

- 版本化语料加载与重复 ID 拒绝；
- 场景和人物存在性检查；
- 通过事件构造评估物品、位置、关系和历史，不直接修改权威投影字段；
- 模型采用状态、因素引用、记忆引用、事件副作用、泄漏、令牌和延迟评分；
- 单案例局部复测，避免每次修改都重复全部付费调用；
- 成对比较与阈值门禁；
- 模型错误接受零价值贿赂时，Python 安全降级且不转移物品。

## 6. 使用方式

完整真实回归：

```powershell
cd apps/server
.\.venv\Scripts\python.exe scripts\evaluate_deepseek_npc_decisions.py --compact
```

只复测失败案例：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_deepseek_npc_decisions.py `
  --case-id harvey-positive-history --compact
```

真实调用需要仅在本机进程环境中提供模型密钥。脚本不把密钥写入报告、审计或仓库。
