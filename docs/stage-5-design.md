# 阶段 5 设计与开发流程：长期记忆正式版

状态：已完成（5A、5B、5C 正式验收）

## 设计边界

长期记忆是由确认事件投影出的可重建读模型，不是聊天摘要，也不是模型的第二个事实库。当前状态问题永远路由到投影；过去发生过什么才查询情节记忆。FTS、混合候选和未来的向量只负责生成候选，进入上下文前必须重新通过来源、实体、作用域、时间、状态和字符预算检查。

## 开发顺序

1. 冻结 `EventStoreBackend` 接口，保证事件追加、幂等、版本冲突、消息来源和重放不依赖 SQLite 或 PostgreSQL。
2. 保持 SQLite 为离线规则测试后端，同时实现 PostgreSQL 表结构、事务适配、中文 n-gram `tsvector` 候选和 pgvector 可选扩展。未配置 embedding provider 时不启动向量路径。
3. 设计迁移指纹：事件数量与序列、事件来源、公开投影摘要、记忆摘要和所有战役读模型表行数必须在迁移前后相同；目标存档已存在时拒绝覆盖。
4. 扩展确定性评估集到 51 项，并单独报告结构化、纯 FTS、混合候选召回、语义改写召回、当前状态误路由、作用域泄漏和拒答失败。
5. 用 240 条带来源事件的压力场景验证候选截断、精确实体优先、一跳 `updates/caused_by` 展开和 Retrieval Trace 的预算轨迹。

## 研究依据与取舍

- Generative Agents（Park et al., 2023）提供经历流与动态检索的启发，但自由文本不具备本项目的事实权威。
- LongMemEval（Wu et al., 2024）将时间、更新、拒答和多会话回忆分开，因此评估不使用单一相似度分数。
- LoCoMo（Maharana et al., 2024）说明长历史的时间/因果问题不能只靠相似度；位置更新和关系因果必须保留显式链。
- A-MEM（Xu et al., 2025）与 THEANINE（2025）支持保留旧记忆和显式链接；本项目只接受事件字段或确定性状态槽生成链接。

## 验收门槛与结果

- 51/51 记忆案例通过，精确召回率 100%。
- 结构化候选召回 100%，混合候选召回 100%，纯 FTS 召回 37.5%；带语义改写的混合召回 100%。
- 当前状态误路由 0、作用域泄漏 0、拒答失败 0、无来源记忆 0。
- 240 事件压力测试确认候选上限在实体约束后应用，并记录截断而不伪装为空结果。
- PostgreSQL 迁移脚本已覆盖事件、消息、来源、命令、记忆、链接、摘要和检索轨迹；本机没有 PostgreSQL 实例，因此真实连接迁移保留为部署验收项，不能宣称已完成生产迁移。
