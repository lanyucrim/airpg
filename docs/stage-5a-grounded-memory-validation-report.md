## 2. 论文如何影响实现

| 研究 | 采用的工程结论 | 本轮边界 |
|---|---|---|
| Generative Agents | 经历流与动态检索 | 反思不能覆盖事件事实 |
| LongMemEval | 事实、跨会话、时间、更新、拒答五类能力 | 先实现事实/时间/拒答路由，更新和多跳进入 5B |
| RMM | 多粒度和检索后校正 | 首期用确定性 Bounding，暂不引入 RL |
| A-MEM | 动态属性与记忆链接 | schema 预留演进方向，但不自动语义连边 |
| LoCoMo | 时间与因果是独立难点 | 时间模式成为结构化查询字段 |
| THEANINE | 保存旧记忆并连接更新 | 不删除过去事实，更新链进入 5B |
| Memory-Driven Role-Playing | Anchoring / Selecting / Bounding / Enacting | 分别对应事件来源、候选、边界检查和受控 NPC 上下文 |
| MemMachine / ReverieMem | 保留可追溯经历核心与角色可见性 | 事件级来源与 player/NPC 作用域先落地 |

## 3. 关键不变量验证

- 玩家原文与 AI 叙述没有写入记忆表的代码路径；
- `source_event_id` 是唯一外键，删除事件会级联删除派生记忆；
- 当前状态请求返回 `current_state_required`，不会选择“最新记忆”冒充当前状态；
- 双方历史要求所有实体同时匹配，而不是命中任意一个名字；
- NPC 私有关系变化只属于 subject NPC；
- 记忆正文不通过普通回合详情接口返回；
- 事务在事件落库并关联来源消息后写记忆，失败整体回滚；
- 幂等重放不会增加事件、记忆、轨迹或模型调用；
- 全量重建前后记忆业务字段一致，当前投影完全不变；
- 候选查询计划使用 `idx_memory_entities_entity`。

## 5. 自我复盘与修正

### 5.1 没有为测试强行统一安全拒绝码

“我前天送过一瓶酒”当前会先因为世界中没有可解析的酒而得到 `missing_reference`；另一种有实体的历史声称会得到历史未证实类结果。两者都满足“零事件记忆、零状态变化”。本轮保留真实解析边界，并把两种路径都纳入验收，后续可单独改善玩家提示文案。

### 5.2 修复了假运行的网页进程

第一次访问 3000 端口失败，但进程管理器仍显示旧 Node 进程。检查确认该进程没有监听端口后，只终止这一明确 PID 并重启网页；随后构建、渲染和浏览器验收均通过。

### 5.3 区分环境失败和代码失败

第一次前端命令因终端找不到 Node 而未执行。改用工作区固定 Node/pnpm 运行时重新执行，得到真实的 lint、构建和测试结果；没有把环境报错算作代码失败或伪装成通过。

### 5.4 没有提前引入向量库

首期最重要的风险是记忆污染、越权和把旧状态当当前状态，不是语义召回率。先完成来源、作用域、时间、轨迹和重建，能够让下一阶段用评估数据证明向量检索是否值得增加复杂度。

## 6. 已知限制

- 当前允许列表聚焦赠礼、贿赂和关系变化；调查、承诺、犯罪、通缉、知识与信念尚未全部进入记忆投影；
- 当前作用域只有 player/NPC，公开、场景、阵营和传播作用域待阶段 6；
- 更新、纠正、因果链接、场景摘要、全文和向量候选尚未实现；
- SQLite 候选上限当前为 200，未来需由长期评估确定分页和数据库迁移时机；
- 记忆摘要当前为确定性模板，表达较朴素，但不会增加未发生事实。

这些限制均不会破坏当前事件权威、状态重放或既有阶段功能。
