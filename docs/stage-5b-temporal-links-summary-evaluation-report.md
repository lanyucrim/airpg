## 关键行为

### 旧事实不会消失

艾拉从大厅到厨房、再回到大厅时，两条移动记忆都保留为 `active`。第二条通过 `updates` 指向第一条；“现在在哪里”仍直接读取当前投影，“之前去过哪里”才读取历史链。

### 因果不能靠相似度猜

只有事件载荷的 `sourceEventId` 能建立 `caused_by`。例如 `relationship.changed` 可以指回确实导致变化的 `gift.accepted`；找不到对应记忆时不建链接，也不生成替代原因。

### 摘要不是事实来源

摘要只组合已经锚定的情节记忆，保存：

- scene 与地点片段；
- 起止事件序号和世界时间；
- rolling / closed 状态；
- Python 模板生成器及版本；
- 已解决/未解决事项；
- 全部来源事件和来源记忆。

普通调试接口只返回上述元数据，不返回可能包含 NPC 私密关系的摘要正文。

## 自我复盘与主动修正

### 修正一：拒绝每回合全量重写记忆

第一版实现为了简单，在每个状态变化回合后全量删除并重建记忆读模型。它虽然正确，却会让长期战役产生 O(n) 数据库写入，也会改变旧读模型行的创建时间。审查后改成正常回合只投影新增事件；全量重建只用于启动迁移、修复和一致性验证。

### 修正二：锚点查询从全表扫描缩小到本轮需要

增量版最初会读取整个战役的来源与更新槽索引。现已改为只查询本轮 `sourceEventId` 和本轮涉及的更新槽，并为真实查询建立部分索引。

### 修正三：来源 ordinal 必须可重建一致

最初增量摘要用“已有摘要末尾 + 1”生成来源顺序，而全量重建使用数组顺序；虽然阅读结果相同，但业务字段不完全一致。现统一使用权威事件 sequence 作为 ordinal，并把来源表纳入重建一致性测试。

### 修正四：迁移索引的创建时机

`update_key` 索引不能在旧表增加字段前创建。索引创建已移入迁移步骤，并增加真实的 v1 缺字段升级测试，避免旧存档启动失败。

### 修正五：候选上限必须在精确实体匹配之后

位置记忆加入后，如果先按“命中任意实体”截取 200 条，再检查双方实体，玩家较新的移动历史可能挤掉更早但真正相关的 NPC 互动。候选 SQL 已改成先要求全部实体同时匹配，再排序和应用上限，并用“更新的移动记录不能挤掉哈维历史”回归测试固定该行为。

## 已知限制

- 位置是首个更新槽；物品所有权、任务、通缉和信念需要各自领域事件稳定后再加入；
- 当前摘要以地点切换为片段边界，不等于阶段 7 的完整导演场景状态机；
- 当前评估只有 18 项，尚未覆盖 200+ 事件候选压力和自然语言同义表达；
- 当前仍是结构化精确候选，没有全文或向量检索；
- 链接尚未自动展开进入 NPC 上下文，5C 将先实现受约束的一跳展开。

这些限制不会改变事件权威、当前状态、角色作用域或既有 NPC 决策边界。
