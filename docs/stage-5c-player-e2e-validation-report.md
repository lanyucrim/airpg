# 阶段 5C 真实玩家端到端验证报告

日期：2026-08-20  
范围：DeepSeek 玩家意图、叙述、NPC 决策、长期记忆写入、回合审计、网页交互与重启持久化

## 1. 验证目标

本轮不只运行确定性单测，而是以玩家方式从《灰港》开局提交自然语言行动，确认模型只能
提出候选，Python 仍是状态、规则、事件和物品所有权的唯一权威。测试使用独立 SQLite
存档，未修改正式本地开局。

## 2. 玩家回合覆盖

按顺序执行了以下动作：

- 查看铁钩帮最后通牒；
- 用相同幂等键重复提交；
- 查看白鹭屋营业账本并核对债务数字；
- 进入厨房并返回一楼大厅；
- 等待十分钟；
- 向玛莎询问债务来源；
- 声称过去曾送过哈维小刀；
- 把小刀递给哈维，请求在催款上通融。

模型驱动回合中，意图解析 8/8 次采用 DeepSeek 候选；赠礼/贿赂动作由本地权威解析器
保留，因为物品转移属于高风险本地边界。NPC 决策 1/1 次采用 DeepSeek 的拒绝提案，
叙述器在大多数回合采用模型输出；被校验器拒绝的叙述安全回退到确定性原文，没有重算
状态或增加事件。

## 3. 权威边界结果

| 检查项 | 结果 |
|---|---|
| 最后通牒、账本和询问事件 | 均生成确认事件并推进一个版本 |
| 重复幂等键 | `replayed=true`，不重复事件、不重复记忆 |
| 虚构过去赠礼 | `claim_disputed`，只记录主张核验，不生成赠礼记忆 |
| NPC 拒绝贿赂 | `bribe.rejected`，小刀仍在玩家背包，附带请求未执行 |
| 旧状态版本 | HTTP 409，返回当前版本 |
| 重启持久化 | 状态版本、世界时间、地点、线索和背包一致 |
| NPC 私有审计 | 只显示采用状态、模型、令牌和延迟，普通接口不返回请求/响应正文 |

隔离存档最终状态版本为 12，世界时间为 57 分钟；事件、消息、记忆、场景摘要和检索
轨迹均可从 SQLite 审计表追溯。正式开局没有写入本轮测试数据。

## 4. 网页验收与修复

首次网页提交回合时发现 `TurnDetailResponse` 未声明 `retrieval_traces` 和
`scene_memory_summaries`，前端开发追踪直接访问缺失数组导致运行时错误。已完成两层修复：

1. 后端 schema 显式返回不含私密正文的检索轨迹和场景摘要元数据；
2. 前端对旧服务或缺字段响应归一化为空数组，避免追踪面板影响游戏主流程。

修复后重新提交等待回合，页面正常显示世界版本、模型意图审计、叙述审计、来源链和确认
事件。新浏览器标签无运行时错误或控制台错误。

## 5. 自动验证

- 后端：174 项测试全部通过；总覆盖率 93%。
- 长期记忆：18/18，精确匹配率 100%，作用域泄漏 0，拒答失败 0，当前状态误路由 0。
- 前端：lint、生产构建和 SSR 渲染测试全部通过。
- API：回合详情追踪字段测试通过，私密正文仍不出现在普通响应。

## 6. 结论与下一步

阶段 5C 第一版的真实玩家纵向切片通过。剩余工作不是放宽权限，而是把长期记忆语料扩充
到至少 50 项、加入 200+ 事件压力场景，并对结构化、FTS 和混合检索做同一语料下的
Recall、Precision、越权率、过时事实率、拒答率和候选成本对照。
