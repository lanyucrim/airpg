# 阶段 7.5B—7.5C：权威内核与环境机会首个切片报告

状态：首个切片完成，领域迁移继续进行

日期：2026-08-20（后续交易切片于 2026-08-21 更新）

## 本轮实现

- 新增 `EventStorePort`、`CommandResolver`、`ProjectionRunner`、`NarratorPort` 和 `NarrativeResult` 契约。
- 新增 `AuthoritativeTurnPipeline`，把解析、记忆选择后的 NPC 决策、规则结算、后果传播、Director 校验、重放预测和叙述准备集中为无写锁流水线。
- `GameService` 先运行预提交流水线，再重新检查幂等键和状态版本，最后才写入数据库。
- 新增注册式投影处理器，首批迁移 `campaign.created`、地点、人物、组织、容器、物品、NPC 日程、时间和环境机会事件。
- 保留旧 `engine.py` 和 `projection.py` 分支作为兼容回放路径；兼容入口不再承载新的回合协调逻辑。
- 开局物品运行时携带类别、关键性、故事绑定政策和标准操作，玩家背包可以看到这些公开元数据。
- 新增 `environment.py`，普通环境搜索不再和隐藏通路调查共用实现。
- 街道、市场、码头、酒馆等合理地点的找食物/饮品请求可以提交 `affordance.observed`，返回有来源的临时机会，不会凭空创建物品或改变背包。
- 搜索无结果仍提交 `search.performed` 和时间消耗，明确区分“没有找到”和“行动非法”。
- 新增 `routine.py` 的结构化日常候选边界：日常候选只能引用已观察机会，只能产生 `routine/soft` 影响和普通/情境物品。

## 权威边界

```text
玩家输入
  → 意图解析
  → 环境机会/记忆上下文
  → AI 或规则候选
  → 结构与领域校验
  → 确认事件
  → 注册式投影
  → 玩家可见叙述
```

- 临时机会不是库存；观察机会不是拥有物品。
- 日常候选不是事件，不能直接写投影。
- `story`/`major` 候选在 Schema 层拒绝；关键道具只能由剧本边界和独立绑定事件产生。
- 旧事件仍由兼容分支重放，新事件优先走注册式处理器。
