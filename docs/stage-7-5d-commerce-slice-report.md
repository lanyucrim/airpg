# 阶段 7.5D：统一物品与交易生命周期首个交易切片

状态：首个交易切片完成，迁移继续进行

日期：2026-08-21

## 本轮实现

- 增加 `balances_pence`、`commerce_offers` 和 `commerce_transactions` 投影字段。
- 增加 `currency.balance_initialized`、`money.transferred`、`commerce.offer_found`、`commerce.completed` 与 `item.purchased` 的注册式投影处理器。
- 新增纯 Python `commerce.py` 校验与购买解析：报价必须来自已观察机会，购买同时检查地点、库存、余额、数量和背包容量。
- 购买按“货币转移 → 物品实例化 → 交易完成 → 时间推进”形成单回合事件链；物品实例保留购买事件来源，报价库存由交易完成事件递减。
- 环境搜索在观察到食物/饮品机会后产生有来源的临时报价；报价不是库存，只有购买事件才产生玩家物品实例。
- 统一物品模型补齐堆叠标记；转移支持堆叠数量拆分，取用和赠礼会检查目标容器容量。
- 后端公开状态增加玩家余额和当前位置可见报价，不暴露卖方私密状态；网页尚未把这些字段做成购买控件。

## 验证

- 物品、环境和交易专项测试通过。
- 交易专项覆盖成功重放、余额不足、库存不足、数量和容量校验。
- 新事件处理器固定 `schemaVersion=1`，未知版本拒绝重放。
- 修复一次迁移兼容回归：旧版 `item.created` 缺少 `operations` 时，赠礼仍按历史契约允许转移；显式声明操作的物品继续接受标准操作校验。
