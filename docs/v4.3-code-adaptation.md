# V4.3 剧本代码适配清单

> 本文件只描述未来代码需要如何适配 V4.3，不属于剧情 Canon。

## 1. 剧本源与编译器

当前 `story/v4_compiler.py` 主要从 V4.2 Markdown 编译：

- Canon 层级；
- 九幕主线；
- 60 个月时间线；
- 支线；
- 地点/人物/组织/关键道具等。

V4.3 需要增加新的结构化字段，而不是继续把推进规则只保存在自然语言 excerpt 中。

建议把主线阶段编译成：

```json
{
  "powerStage": "M2",
  "windowStateModel": ["LOCKED", "BACKGROUND", "AVAILABLE", "ACTIVE", "SETTLED"],
  "backgroundConditions": [],
  "availabilityConditions": [],
  "activationConditions": [],
  "completionEvidence": [],
  "gapRepairEvidence": [],
  "calendarBindings": []
}
```

时间线条目增加：

```text
calendarKind = HARD_CALENDAR | BACKGROUND_WINDOW | STORY_OPPORTUNITY
```

支线条目增加：

```text
formationConditions
playerExposureChannels
playerEntryActions
backgroundActors
escalationConditions
expirationConditions
mainEvidence
```

## 2. Projection 增加 Story Runtime 状态

当前 Projection 已有 `clocks / story_conditions / world_facts / knowledge / cognitions / schedules / relationships` 等，但 V4.3 还需要剧情一等状态：

```text
mainline_windows: dict[Mx, MainlineWindowState]
power_stages: dict[Mx, ACHIEVED|UNACHIEVED]
power_gaps: set[str]
mainline_flags: set[str]
quest_instances: dict[quest_instance_id, QuestState]
```

建议事件：

```text
story.mainline_window_changed
story.power_achieved
story.power_gap_added
story.power_gap_repaired
story.quest_instantiated
story.quest_status_changed
story.quest_expired
story.mainline_evidence_recorded
```

所有状态变化必须来自确认事件。

## 3. Clock 与“剧情事件”解耦

现有白鹭屋 `white_heron_seven_day_deadline` 可以继续使用。

到期时程序只确认：

```text
clock crossed deadline
```

然后剧情规则读取当前债务、产权、人物、保护、合同和位置状态，决定生成哪一种“债务处置候选”。

不能继续把：

```text
clock expired -> M1 failed -> M2 starts
```

写死成单链。

## 4. World Director 改造

当前 Director 主要按周/月生成报告候选。

V4.3 建议增加三类候选：

```text
hard_calendar_candidate
background_world_candidate
story_opportunity_candidate
```

Director 只提出候选，不直接提交主线结果。

### HARD_CALENDAR

可以由时间直接提出，例如选举、已确定的债务期限。

### BACKGROUND_WORLD

需要同时满足时间窗口和当前世界条件。

### STORY_OPPORTUNITY

不能只看时间，还必须读取玩家资源、地点、关系、已有知识、组织规模等。

## 5. 玩家是否知道任务必须与任务是否形成分离

`quest AVAILABLE` 不能直接显示在玩家 UI。

需要：

```text
quest formed in world
    !=
player has learned about quest
```

玩家端只显示已经通过：

- witnessed event；
- dialogue；
- clue；
- report；
- document；
- rumor/cognition；
- direct impact；

等渠道进入玩家认知的内容。

## 6. 支线后台结算

每条支线未来应允许 `backgroundActors`。

当玩家不介入时，世界模拟器可以根据：

- NPC 当前状态；
- 组织资源；
- 时间；
- 地点；
- 已发生事件；

提出：

```text
background resolution / escalation / expiration
```

仍要经过验证与事件提交，不能由 AI 一句话结算。

## 7. 自由活动不触发剧情补偿

当前 routine/soft 边界继续保持。

需要避免出现：

```text
player rests -> system selects unused story event to keep engagement
```

正确行为：

```text
player rests
-> time advances
-> daily/weekly/monthly boundaries settle normally
-> only independently due/formed events change world
```

## 8. 自动剧情节奏冷却不是硬时间冷却

V4.3 所说“不要连续塞重大剧情”不建议实现成固定 24 小时 cooldown。

更合理的是 Director 的候选排序：

1. 已到期紧急 Clock；
2. 已直接作用于玩家资产/安全的事件；
3. 玩家主动追查方向；
4. 已知但不紧急的问题；
5. 仅后台形成的问题。

叙述器仍受 `maxMajorBeatsPerTurn` 限制。

## 9. NPC Schedule 与实际位置分离

当前 `scheduled_npc_state()` 可以用于判断“按计划应该在哪/是否可预约”。

未来自治完成前，不要把 schedule 查询结果直接永久写成实际位置。

建议新增：

```text
npc.movement_planned
npc.moved
npc.schedule_deviated
```

剧情触发读取真实位置，而 schedule 只作为行动候选来源。

## 10. V4.3 支线包编译

新增 `SQ095-SQ120` 应加入 Catalog，但保持 G 层 template：

```text
instantiated = false
```

直到 Story Runtime 生成：

```text
story.quest_instantiated
```

才成为本局 C1 世界事实。

## 11. 当前文件迁移

最终迁移时：

1. `manifest.sourceVersion` 改为 `4.3`；
2. sourceDocument 指向 V4.3 主文件或由编译器支持“V4.2 基础 + V4.3 override + V4.3 sidequest pack”多源编译；
3. 重新生成 source SHA；
4. catalog schema 升级；
5. 旧 V4.2 存档保持旧 content hash，可继续 replay；
6. 新战役默认 V4.3；
7. 不要让旧存档无迁移地自动套用 V4.3 状态机。

## 12. 推荐开发顺序

```text
ST-01 Story Runtime state/events
ST-02 Mainline window conditions
ST-03 Quest instantiation/status
ST-04 Hard calendar settlement
ST-05 Background quest/world resolution
ST-06 Player exposure/knowledge bridge
ST-07 Director candidate ordering
ST-08 UI known-problem projection
ST-09 V4.3 compiler/catalog migration
```

第一条验证链仍建议使用白鹭屋：

```text
7-day clock
-> debt settlement candidate
-> current facts determine outcome
-> M1 power evidence independent
-> M2 may become BACKGROUND but is not automatically shown to player
```

第二条验证链使用一个生活型支线，例如 SQ095 或 SQ118，证明：

```text
quest can form
-> player may never know
-> background actor can resolve it
-> no mainline evidence is generated
```
